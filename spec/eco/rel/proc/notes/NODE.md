# ECO.REL.PROC.NOTES: Release notes generator

## Purpose

Generates `release-notes.md` for a release from an exported list of merged PRs since the previous release on the same channel, grouped by label, and attaches the generated reports the release must carry: parity, status, release numbers, the gate verdict (with Tier 2 notes), the evidence-bundle statement digest and the count of high residual-risk threats. The generator is a pure function of its input files, so the notes can be regenerated and checked.

## Scope

**In:**
- PR grouping by label (`feature`, `fix`, `security`, `breaking`, `docs`, `internal`; unlabelled goes to "Other")
- The attachments list and the generated header
- `cargo xtask rel notes`

**Out:**
- Exporting PRs from the code host (a workflow step in `ECO.REL.PROC.FLOW`)
- Content of the attached reports (owned by their producers)
- Announcements (owned by `OUTR`)

## Requirements

- **REQ-ECO.REL.PROC.NOTES-001** The notes shall list every PR in the export merged after the previous release tag on the same channel and up to the current tag, once each, grouped by its first label in the fixed label order.
- **REQ-ECO.REL.PROC.NOTES-002** The notes shall link `parity.json`, `parity.md`, `status.json`, `status.md`, `release-numbers.json` and `release-gates.json` with the SHA-256 of each, and shall fail if any is missing.
- **REQ-ECO.REL.PROC.NOTES-003** The notes shall list every Tier 2 build failure reported in `release-gates.json`, the evidence-bundle statement digest from `QUAL.EVID`, and the number of `high` residual-risk entries in the `QUAL.THREAT` register.
- **REQ-ECO.REL.PROC.NOTES-004** The notes shall start with the line "Generated by fid-xtask rel notes. Do not edit." and the release version, channel and commit.
- **REQ-ECO.REL.PROC.NOTES-005** PR titles shall be treated as untrusted text: Markdown control characters shall be escaped and titles longer than 200 characters truncated with a marker.

## Acceptance criteria

- **AC-1** Given fixture `fixtures/rel/notes/basic/` (12 PRs with labels, previous tag `v1.3.0` on stable, current `v1.4.0`), when `cargo xtask rel notes --tag v1.4.0 --channel stable --prs prs.json --reports reports/ --out out/` runs, then `out/release-notes.md` equals `expected.md` byte for byte.
- **AC-2** (error path) Given `missing-status/` (no `status.json`), then it exits 1 with `NOTES-MISSING status.json`.
- **AC-3** Given a PR titled `Fix [link](javascript:x) and *bold*`, then the title appears escaped and no link is rendered.
- **AC-4** Given `tier2-fail/` with one Tier 2 build failure in `release-gates.json`, then the notes contain a "Tier 2 build failures" section naming it.

## Design

- **Registry command(s):** none; repository tool `cargo xtask rel notes --tag <t> --channel <c> --prs <json> --reports <dir> --out <dir>`. Writes into a local output root (W1).
- **Data structures:** `prs.json`: list of `{number, title, labels, merged_at, merge_commit}`; tag history from VERSION's history file.
- **Algorithm:** filter by commit range (export carries membership), sort by PR number within groups, render Markdown, append attachments table and summary lines.
- **Errors:** `NOTES-MISSING(file)`, `INPUT-PARSE` (exit 2).
- **Determinism:** D0.
- **Performance budget:** 2 000 PRs in under 1 s.
- **Crate:** `fid-xtask` (module `rel::notes`).

## Open questions

- Label names follow the repository's label set, which is not yet defined anywhere; ECO.COMM may own it.
- Assumptions the implementation (`fid-xtask` `rel::notes`, PR #185) makes where this node is silent; each is a hypothesis to confirm or change:
  - **`prs.json` shape.** It is an object `{tag, channel, previous_tag, commit, prs: [...]}`, not a bare list, because nothing else supplies the previous tag or the release commit (VERSION has no history file; the CHANNEL `history.json` is not built). `tag` and `channel` must equal the command-line values; `previous_tag` is a tag on the same channel with lower precedence, or `null` for a channel's first release; `commit` and every `merge_commit` are 40 or 64 lowercase hex digits; each PR number appears once. The export step (`ECO.REL.PROC.FLOW`) owns range membership.
  - **Label precedence.** A PR goes to the group of whichever of its labels comes first in the fixed order (feature, fix, security, breaking, docs, internal), not to its `labels[0]`, because code hosts do not order labels. Labels compare ASCII case-insensitively.
  - **Evidence digest.** The SHA-256 of `<reports>/evidence/statement.json` (the `QUAL.EVID.LAYOUT` statement).
  - **High threat count.** `counts.high` of `<reports>/threat/register-summary.json`, schema `qual-threat-summary/1` (`QUAL.THREAT.REG`); when `high_ids` is present its length must match.
  - **Tier 2 build failures.** The `notes` strings of the gate with ID `pkg-plan` in `release-gates.json`. This is an assumption about the output of `ECO.REL.PROC.GATES`, which is not built yet; the notes fail closed (exactly one gate `pkg-plan`, exact ID, with a `notes` array, each note at most 1 024 bytes, else `INPUT-PARSE`).
  - **Title rendering.** REQ-005's escaping is done by showing each title (and gate note) as a CommonMark code span with a fence longer than any backtick run in it, after control and format (Cf) characters become spaces and the text is cut to 200 characters. Backslash escapes alone would not stop GitHub's bare-URL, `www.` and e-mail autolinks or `@mention`s.
