# ECO.REPO.TPL.PROMOTE: Library promotion procedure and tool

## Purpose

When a library outgrows the monorepo, it moves into its own repository without losing history: a tool extracts the library's folder history into a new repository, applies the template on top as one extra commit, and rewrites every consumer's dependency to a git dependency pinned to the new repository's 40-hex revision. `PROMOTE.md` lists the human steps around it (RFC, creating the remote, protecting tags).

## Scope

**In:**
- `PROMOTE.md`: steps, roles and checks
- `python -m repo_template promote --source <monorepo> --path <crate dir> --id <repo-id> --out <dir>`: history extraction and template application
- `python -m repo_template repin --workspace <monorepo> --crate <name> --url <new repo url> --rev <40-hex>`: consumer rewrite
- Verification: commit count and file-content digest of the library at the split point equal before and after

**Out:**
- Deciding to promote (RFC under ECO.COMM) and creating the remote (a maintainer)
- The pin rule and check (owned by `ECO.REPO.TOPO`)

## Requirements

- **REQ-ECO.REPO.TPL.PROMOTE-001** The extracted repository shall contain every commit of the source repository that touched the library path, with original authors, dates and messages, and the tree digest of the library path at the last extracted commit shall equal the source's.
- **REQ-ECO.REPO.TPL.PROMOTE-002** The tool shall apply the template as exactly one commit on top of the extracted history, without changing any file of the library.
- **REQ-ECO.REPO.TPL.PROMOTE-003** The repin step shall replace every path dependency on the promoted crate in the workspace with a git dependency to the new repository's URL and the given 40-hex `rev`, and the workspace shall then pass the `ECO.REPO.TOPO` pin check.
- **REQ-ECO.REPO.TPL.PROMOTE-004** If the source working tree has uncommitted changes, then the tool shall refuse to run.
- **REQ-ECO.REPO.TPL.PROMOTE-005** The tool shall not push to any remote; pushing is a documented human step in `PROMOTE.md`.

## Acceptance criteria

- **AC-1** Given fixture monorepo `fixtures/repo/tpl/promote/mono.bundle` (a git bundle with crates `fid-a` and `fid-b`, 12 commits, 5 touching `crates/fid-b`), when `promote --path crates/fid-b --id fid-b` runs, then the output has 6 commits (5 extracted plus the template commit) and the library tree digest equals the source's.
- **AC-2** Given the result and new revision `<r>`, when `repin --crate fid-b --url https://example.invalid/fid-b --rev <r>` runs on the monorepo, then `fid-a`'s dependency is a git dependency with `rev = "<r>"` and `cargo xtask pins` passes with a fixture `repos.toml`.
- **AC-3** (error path) Given an uncommitted change in the source, then `promote` exits 1 with `PROMOTE-DIRTY`.
- **AC-4** Given the tool run, when the output repository's remotes are listed, then there are none.

## Design

- **Registry command(s):** none; Python standard-library tool calling `git` (W1, writes only the output folder and, for repin, the workspace manifests).
- **Data structures:** none new.
- **Algorithm:** history extraction by `git` subtree-split style filtering limited to the path [unverified: choice between built-in subtree split and a filter tool, both preserve authorship]; template commit via `ECO.REPO.TPL.FILES`; repin with a bounded TOML editor that preserves formatting of untouched lines.
- **Errors:** `PROMOTE-DIRTY`, `PROMOTE-PATH-NOT-FOUND`, `PROMOTE-DIGEST-MISMATCH`, `REPIN-NO-DEPENDENTS`.
- **Determinism:** D0 for identical inputs (commit IDs follow from preserved metadata; the template commit uses fixed author and date given on the command line).
- **Performance budget:** n/a.
- **Crate:** not Rust; `tools/repo_template/promote.py` (standard library) and `PROMOTE.md`.
