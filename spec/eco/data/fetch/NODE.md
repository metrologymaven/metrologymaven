# ECO.DATA.FETCH: Dataset fetch, cache and verify tool

## Purpose

Fetches catalogue datasets into a local cache, verifies each against its SHA-256 before it becomes visible, and serves later requests fully offline. Tests, benchmarks, examples and CI all get datasets through this one tool, so a corrupted or swapped file can never reach a result.

## Scope

**In:**
- `cargo xtask data fetch <id>... | --all | --owner <DOMAIN>`, `data path <id>`, `data verify`
- A library function `dataset_path(id)` for tests, which never downloads in `--offline` mode
- Cache layout, atomic install, mirror fallback order, offline mode

**Out:**
- Catalogue content and admission (owned by `ECO.DATA.CAT`)
- Hosting of mirrors (open question on `ECO.DATA`)
- CI caching between runs (owned by `ECO.CI.WF`)

## Requirements

- **REQ-ECO.DATA.FETCH-001** If a downloaded file's SHA-256 or size differs from the catalogue, then the tool shall delete the temporary file, leave the cache unchanged and fail with `FETCH-DIGEST` naming the dataset and URL.
- **REQ-ECO.DATA.FETCH-002** When a dataset is already in the cache and its digest verifies, the tool shall return its path without any network access.
- **REQ-ECO.DATA.FETCH-003** While `--offline` is set or `FID_DATA_OFFLINE=1`, if a requested dataset is not cached, then the tool shall fail with `FETCH-OFFLINE` and make no network request.
- **REQ-ECO.DATA.FETCH-004** The tool shall try each URL of an entry in catalogue order and stop at the first one that verifies.
- **REQ-ECO.DATA.FETCH-005** A dataset shall appear in the cache only by an atomic rename after verification, so an interrupted fetch never leaves a partial file at the final path.
- **REQ-ECO.DATA.FETCH-006** The tool shall refuse responses larger than the catalogue `size_bytes` and shall stop reading at that limit.

## Acceptance criteria

- **AC-1** Given catalogue `fixtures/fetch/catalogue.toml` whose entry `tiny` points at a test HTTP server serving `fixtures/fetch/tiny.bin`, when `cargo xtask data fetch tiny --cache <tmp>` runs, then it exits 0 and `<tmp>/tiny/<sha256>/tiny.bin` exists with the catalogue digest.
- **AC-2** Given AC-1's cache, when `data fetch tiny --cache <tmp> --offline` runs with the server stopped, then it exits 0 and the server log shows no request.
- **AC-3** (error path) Given entry `corrupt` whose server returns bytes differing from the catalogue digest, when fetched, then it exits 1 with `FETCH-DIGEST corrupt` and `<tmp>` contains no file for `corrupt`.
- **AC-4** Given entry `mirrored` whose first URL returns 404 and second URL serves the right bytes, when fetched, then it exits 0 and the log shows both attempts in order.
- **AC-5** (error path) Given an empty cache and `--offline`, when `data fetch tiny` runs, then it exits 1 with `FETCH-OFFLINE` and no request is made.
- **AC-6** (error path) Given entry `oversize` whose server streams more bytes than `size_bytes`, when fetched, then it exits 1 with `FETCH-SIZE` after reading at most `size_bytes + 1` bytes.
- **AC-7** Given a cache file altered after install, when `data verify --cache <tmp>` runs, then it exits 1 and names the dataset.

## Design

- **Registry command(s):** none; repository tool. `side_effect: W1` because it writes only into the local cache root.
- **Data structures:** cache root (default per-user cache directory, overridable by `--cache` or `FID_DATA_CACHE`); layout `<root>/<id>/<sha256>/<filename>`; temporary files in `<root>/.tmp/`.
- **Algorithm:** stream download into a temp file while hashing; enforce the size cap; compare; fsync; rename. HTTP over TLS through a small client on the licence allowlist; `file://` URLs supported for tests and local mirrors.
- **Errors:** `FETCH-DIGEST`, `FETCH-SIZE`, `FETCH-OFFLINE`, `FETCH-ALL-URLS-FAILED`, `FETCH-UNKNOWN-ID`, `FETCH-IO`.
- **Determinism:** D0 for the cache content (bytes are fixed by digest).
- **Performance budget:** hashing at no less than 300 MB/s on the reference CI machine [unverified].
- **Crate:** `fid-data`.

## Test fixtures

Small binary files generated by a seeded script under `fixtures/fetch/`, served by an in-process test HTTP server; no external network in tests.

## Build prompt

> In crate `fid-data` (implementation repository), add fetch, cache and verify. Commands via `fid-xtask`: `data fetch <id>...|--all|--owner <DOMAIN> [--cache <dir>] [--offline]`, `data path <id>`, `data verify`. Library: `dataset_path(id) -> Result<PathBuf, DataError>` honouring `FID_DATA_OFFLINE` and `FID_DATA_CACHE`. Read the catalogue from `datasets.toml` (format from ECO.DATA.CAT). Download each URL in order; stream to `<root>/.tmp/` while computing SHA-256; abort past `size_bytes`; on match fsync and atomically rename to `<root>/<id>/<sha256>/<filename>`; on mismatch delete temp and try the next URL; report `FETCH-DIGEST`, `FETCH-SIZE`, `FETCH-OFFLINE`, `FETCH-ALL-URLS-FAILED`, `FETCH-UNKNOWN-ID`, `FETCH-IO`. Support `file://`. Tests for AC-1..AC-7 of spec node ECO.DATA.FETCH with an in-process HTTP server and no external network. No `unwrap`/`expect`/`panic`/`unsafe` in non-test code; HTTP and hashing dependencies must pass the licence check.
