# ECO.PARITY.GEN: Parity report generator

## Purpose

Turns a trace document into the published parity report: live/total per seed file and per seed area, with deliberately out-of-scope rows in their own column, as `parity.json` and `parity.md`, each marked "generated, do not edit" and stamped with the inputs they came from. The release workflow calls it once per release and attaches the output.

## Scope

**In:**
- Aggregation per seed file and per area (the first two segments of a seed ID, e.g. `GOM.ALN`)
- JSON and Markdown rendering with a fixed header
- `--release <tag>` mode that writes into the release asset directory

**Out:**
- The live rule (owned by `ECO.PARITY.TRACE`)
- The regeneration check (owned by `ECO.PARITY.DRIFT`)
- Per-app status (owned by `ECO.PARITY.STATUS`)
- Release assembly and upload (owned by `ECO.REL`)

## Requirements

- **REQ-ECO.PARITY.GEN-001** For each seed file and each seed area, the report shall give the count of live rows, the count of in-scope rows and the count of out-of-scope rows, and the percentage live of in-scope rows rounded down to a whole number.
- **REQ-ECO.PARITY.GEN-002** Both outputs shall start with a header that says "Generated by fid-xtask parity. Do not edit." and gives the spec-tree revision, registry manifest SHA-256 and test report SHA-256 from the trace.
- **REQ-ECO.PARITY.GEN-003** The Markdown report shall list every in-scope row that is not live, with its reason code, under its area.
- **REQ-ECO.PARITY.GEN-004** When run with `--release <tag>`, the generator shall write `parity.json` and `parity.md` into `<out>/<tag>/` and the release workflow shall attach both files to the release.
- **REQ-ECO.PARITY.GEN-005** Given the same trace, the generator shall produce byte-identical output on every supported OS.

## Acceptance criteria

- **AC-1** Given `fixtures/parity/trace.json` (the AC-1 result of ECO.PARITY.TRACE), when `cargo xtask parity gen --trace fixtures/parity/trace.json --out <tmp>` runs, then `parity.json` gives area X.A: live 1, in-scope 2, out-of-scope 0, 50 %; area X.B: live 0, in-scope 1, out-of-scope 1, 0 %.
- **AC-2** `parity.md` matches the golden file `fixtures/parity/parity.golden.md` byte for byte.
- **AC-3** Both files start with the generated header including the three input identifiers from the trace.
- **AC-4** With `--release v0.1.0`, the files appear under `<tmp>/v0.1.0/`.
- **AC-5** (determinism) Running on Windows, Linux and macOS in CI produces identical bytes (LF line endings).
- **AC-6** (error path) Given a trace whose `inputs` header is missing, the generator exits 1 with `PARITY-TRACE` and writes nothing.

## Design

- **Registry command(s):** none; repository tool `cargo xtask parity gen --trace <json> --out <dir> [--release <tag>]`. `side_effect: W1`: writes report files into a local output root.
- **Data structures:** `parity.json`: `{header, files:[{file, live, in_scope, out_of_scope, pct}], areas:[...same + not_live:[{id, reason}]]}`, sorted.
- **Algorithm:** group by file and area with BTreeMap; integer arithmetic for percentages; render Markdown tables with a fixed column order; write with LF.
- **Errors:** `PARITY-TRACE`, `PARITY-IO`.
- **Determinism:** D0.
- **Performance budget:** under 1 s for 5 000 seed rows [unverified].
- **Crate:** `fid-xtask` (module `parity`).

## Test fixtures

`fixtures/parity/trace.json` and the golden Markdown, shared with ECO.PARITY.TRACE.

## Build prompt

> In `fid-xtask` (implementation repository), add `parity gen --trace <json> --out <dir> [--release <tag>]`. Read the trace from `parity trace`. Aggregate per seed file and per area (first two dot segments of the seed ID): live, in-scope, out-of-scope and floor(100*live/in_scope) (0 when in_scope is 0). Write `parity.json` and `parity.md` (LF endings) starting with "Generated by fid-xtask parity. Do not edit." and the trace's tree revision, manifest SHA-256 and test-report SHA-256; the Markdown lists each not-live in-scope row with its reason under its area. With `--release`, write into `<out>/<tag>/`. Exit 1 with `PARITY-TRACE` on a trace without `inputs`. Add golden-file tests for AC-1..AC-6 of spec node ECO.PARITY.GEN; run them on three OSes. Use BTreeMap; no floats.
