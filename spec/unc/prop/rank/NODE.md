# UNC.PROP.RANK: Contributor ranking

## Purpose

Ranks the input quantities of an evaluated model by how much each contributes to the output uncertainty, so that explanations, reports and agents can name the largest contributors. For LPU results it uses sensitivities; for MCM-only results it uses an approximate sample-based measure and says so.

## Scope

**In:**
- LPU ranking: |c_i|·u(x_i) and the correlation-aware (Euler) share c_i·(Σc)_i / u_c²
- MCM ranking: squared Pearson correlation between each input's samples and the output samples, labelled `approximate`
- Output as the `contributors` list of the statement

**Out:**
- Computing sensitivities and samples (owned by `UNC.PROP.LPU` and `UNC.PROP.MCM`)
- Displaying them (owned by `UNC.UEC.EXPL`)

## Requirements

- **REQ-UNC.PROP.RANK-001** Given LPU sensitivities c and input covariance Σ, the function shall return for each input u_i(y) = |c_i|·√Σ_ii and the share c_i·(Σc)_i / (cᵀΣc), with shares summing to 1 within 1e-12.
- **REQ-UNC.PROP.RANK-002** Given only Monte Carlo input and output sample sets, the function shall return for each input the squared Pearson correlation with the output, computed with fixed-order reductions, and set `method = approximate_src2`.
- **REQ-UNC.PROP.RANK-003** The returned list shall be sorted by descending u_i(y) (LPU) or squared correlation (MCM), ties broken by input ID.
- **REQ-UNC.PROP.RANK-004** If cᵀΣc is zero or the output sample variance is zero, then the function shall return the contributors with shares absent and flag `degenerate`, never dividing by zero.

## Acceptance criteria

- **AC-1** Given `fixtures/unc/rank/lpu_3in.json` (c = (1, 2, −1), independent u = (0.1, 0.05, 0.2)), when ranked, then the order is x3, x1/x2 tie broken by ID, the shares are (0.01, 0.01, 0.04)/0.06 within 1e-15, and they sum to 1.
- **AC-2** Given `fixtures/unc/rank/lpu_corr.json` (two inputs with ρ = −0.9), when ranked, then the shares match the 50-digit reference in the fixture within 1e-14 and sum to 1.
- **AC-3** Given `fixtures/unc/rank/mcm_samples.bin` (10^5 trials of Y = X1 + 3·X2 with seed `0x52414E4B`), when ranked by samples, then X2 ranks first and `method = approximate_src2`.
- **AC-4** (degenerate) Given all sensitivities zero, then shares are absent and `degenerate` is set.
- **AC-5** (portability) Given AC-1..3, outputs are bit-identical on wasm32, x86-64 and ARM64.
- **AC-H1** Hypothesis: LPU contributor ranking reproduces the order and magnitudes of the published uncertainty budget of the JCGM 100:2008 end-gauge example (H.1 [unverified: annex numbering]), with agreement to the number of significant digits the guide publishes (at most one unit in the last published digit) for each |c_i| u(x_i), measured by comparing the ranked list with the published budget; falsified if the order or any magnitude disagrees.
- **AC-H2** Hypothesis: the `approximate_src2` ranking agrees with the LPU ranking with Kendall tau ≥ 0.9 [unverified] on every case of the JCGM 101:2008 worked examples (additive model, mass calibration, comparison loss, gauge-block calibration [unverified: clause 9 numbering]), encoded from their published input definitions with the published results as reference values where `UNC.PROP.VALID` returns `validated = true`, measured from 10^6-trial sample sets; falsified if any such case is below 0.9. Cases with `validated = false` are reported but not scored.

## Design

- **Registry command(s):** none; kernel algorithm `unc.prop.rank@1.0.0` called by `UNC.PROP.SELECT`.
- **Data structures:** input `RankInput::Lpu { c: Vec<f64>, cov: SymMatrix, ids } | RankInput::Samples { inputs: Vec<SampleRef>, output: SampleRef, ids }`; output `Vec<Contributor>` plus `method` and `flags`.
- **Algorithm:** fixed-order dot products from `fid-num`; stable sort by key then ID.
- **Errors:** `dimension_mismatch`, numeric errors from `fid-num`.
- **Determinism:** D0.
- **Performance budget:** 1,000 inputs × 10^5 samples in under 1 s [unverified until measured].
- **Crate:** `fid-kunc`.

## Open questions

- A variance-based (Sobol-type) ranking for MCM would be more faithful for non-linear models but needs extra trials; deferred.
- **Partial build (not marked built).** AC-1 to AC-5 are implemented and tested in `fid-kunc` (`prop::rank`, spec card `crates/fid-kunc/cards/unc.prop.rank@1.0.0.toml`, tests `crates/fid-kunc/tests/rank.rs`, fixtures from `fixtures/unc/rank/make_fixtures.py`, an independent stdlib reference that emulates the fixed-order reductions and predicts the exact bits and canonical JSON bytes). **AC-H1 and AC-H2 are open:** AC-H1 needs the published JCGM 100:2008 end-gauge budget (H.1 [unverified: annex numbering]) encoded and checked by an expert; AC-H2 needs the JCGM 101:2008 worked examples encoded as models and 10^6-trial sample sets, with `UNC.PROP.VALID` run on each. Neither data set is in the repository, and no published values were transcribed from memory.
- **Recorded build decisions** (maintainer to confirm): (1) `cov` is the full `n * n` row-major matrix and must be exactly symmetric (`not_symmetric{i, j}`), instead of a `SymMatrix` type (none exists in `fid-num`); a negative diagonal is `negative_variance`. A covariance that is not positive semi-definite is refused as `not_positive_semidefinite{i, j}` (review of #685): first a pairwise Cauchy-Schwarz test `S_ij^2 > S_ii S_jj (1 + 4u)` (with a scaled form when a side overflows or underflows), then the pivoted Cholesky of `fid-num` (`la::chol_pivoted`, `rel_tol = 0`), whose remainder after an early stop must be rounding only (bound `4 (r + 1) u (|a| + |L_i| . |L_j|) + (4 r + 4) 2^-1074`). This adds an `O(n^3)` factorization and the `la::MAX_DIM` = 4096 limit on `n`; `c^T S c` below minus its tolerance stays a final `negative_variance` guard. (2) The REQ-004 zero test has a floor at rounding resolution: `c^T S c <= (4 (n + 1) 2^-53) |c|^T |S| |c| + (4 n + 4) 2^-1074` is degenerate (the absolute term covers products that underflow; review of #685), reported as `zero_variance` (exactly 0) or `variance_at_rounding_resolution`. (3) Shares whose fixed-order sum misses 1 by more than 1e-12 are dropped (`shares: sum_out_of_tolerance`) with the sum still reported, never returned as if REQ-001 held. (4) The output is a `RankOutput` of `Ranked` entries rather than `statement::Contributor` directly, because a correlation-aware share can be negative or above 1 and a degenerate ranking has no shares, while `Contributor.variance_share` must lie in `[0, 1]`; `RankOutput::statement_contributors` converts an LPU ranking with all shares in `[0, 1]` and refuses everything else (`not_convertible`). A sample-based ranking never converts: a squared correlation is not a variance share. (5) Samples form: bitwise-constant columns are caught before any mean (`zero_input_variance` for an input, `degenerate` with `zero_output_variance` for the output), a positive `s_xx` or `s_yy` below `2^-1022` gives no `r2` (`below_rounding_resolution`), `r = (s_xy / sqrt(s_xx)) / sqrt(s_yy)` and a rounded `r2` above 1 is reported as 1; the canonical JSON carries the required member `"basis":"simulated"` (D-045). (6) Every tie in the order is reported (`tie_broken_by_id`). (7) Errors beyond Design: `no_inputs`, `invalid_id` and `duplicate_id` (the statement's token rule), `too_few_samples` (fewer than 2), `not_symmetric`, `negative_variance`, `not_positive_semidefinite`, `not_convertible`.
- **Fixture deviation:** AC-3 names `fixtures/unc/rank/mcm_samples.bin`. The build commits `mcm_samples.json` instead: the generation recipe (seed `0x52414E4B`, X1 and X2 rectangular on [-1, 1] on streams 0 and 1, `Y = x1 + 3.0 * x2`, 10^5 trials), the SHA-256 of the three sample columns and the expected result. The test regenerates the samples with `UNC.MODEL.DIST` and must match the reference's digest (computed with its own Philox4x32-10) before ranking, so no 2.4 MB binary is stored. The spec does not name the input distributions; rectangular inputs keep the reference free of libm.
