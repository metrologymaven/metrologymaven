# UNC.XFM.APPLY: Propagating transform covariance into transformed points and features

## Purpose

When a point or feature is expressed in a frame whose transform carries a covariance, its covariance in the new frame must include the transform's contribution. This kernel function computes it to first order: the point's own covariance rotated into the new frame plus the transform covariance mapped through the Jacobian of the transform action, with an optional cross-covariance term when the point and the transform share observations.

## Scope

**In:**
- Points: Σ' = R·Σ_p·Rᵀ + J_T·Σ_T·J_Tᵀ (+ cross terms if supplied)
- Feature parameter vectors (plane, line, circle, sphere, cylinder, cone): the same form with the Jacobian of the transform action on each feature parameterisation
- Parameterisation `se3-left@1` and `sim3-left@1` for Σ_T, matching `UNC.XFM.TCOV`

**Out:**
- Computing Σ_T (owned by `UNC.XFM.TCOV`)
- Chains of transforms (owned by `UNC.XFM.CHAIN`)
- Monte Carlo fields (owned by `UNC.XFM.FIELD`)

## Requirements

- **REQ-UNC.XFM.APPLY-001** Given a point p with covariance Σ_p and a transform T with covariance Σ_T in `se3-left@1`, the function shall return the transformed point and Σ' = R·Σ_p·Rᵀ + J_T·Σ_T·J_Tᵀ, with J_T = [−[Rp + t]× | I] for the left perturbation.
- **REQ-UNC.XFM.APPLY-002** When a cross-covariance between p and the transform parameters is supplied, the function shall add the two cross terms; when it is absent, the output shall record `assumed_independent = true`.
- **REQ-UNC.XFM.APPLY-003** For each supported feature type, the function shall map the feature parameter covariance and Σ_T through the Jacobian of the transform action on that feature's declared parameterisation.
- **REQ-UNC.XFM.APPLY-004** On `fixtures/unc/xfm/apply/` cases, the first-order covariance shall agree with a 10^6-trial Monte Carlo reference within 2 % on every standard deviation when rotation standard deviations are below 1 mrad [unverified].
- **REQ-UNC.XFM.APPLY-005** If Σ_T is in an undeclared parameterisation, or dimensions do not match, then the function shall fail with `parameterisation_mismatch` or `dimension_mismatch`.

## Acceptance criteria

- **AC-1** Given `fixtures/unc/xfm/apply/point_pure_translation.json` (Σ_T with translation-only variance 1e-10 m²), when applied to a point with zero covariance, then Σ' equals the translation block exactly.
- **AC-2** Given `fixtures/unc/xfm/apply/point_rotation.json` (rotation σ = 0.1 mrad about z, point at (1, 0, 0) m), when applied, then σ_y of the output is 1e-4 m within 1e-12 relative and σ_x is 0 within 1e-18 m.
- **AC-3** Given `fixtures/unc/xfm/apply/features_mc.json` (plane, cylinder and sphere with Σ_T and Σ_feature, plus 10^6-trial MC references with seed `0x58464D41`), when applied, then every standard deviation matches within 2 %.
- **AC-4** (error path) Given Σ_T labelled `euler-zyx`, then the call fails with `parameterisation_mismatch`.
- **AC-5** (portability) Outputs of AC-1..3 are bit-identical on wasm32, x86-64 and ARM64.

## Design

- **Registry command(s):** none; kernel algorithms `unc.xfm.apply_point@1.0.0` and `unc.xfm.apply_feature@1.0.0`, called by GDT, ALN reports and `UNC.XFM.FIELD`.
- **Data structures:** `TransformCovariance` (from TCOV); `FeatureParams { kind, params, cov }` with per-kind parameterisation shared with `UNC.PROP.MVAR`; output `{ value, cov, assumed_independent }`.
- **Algorithm:** closed-form Jacobians per feature kind (direction vectors rotate, points rotate and translate, radii unchanged under rigid motion and scaled under Sim(3)); matrix products via `fid-num` with fixed-order reductions; symmetrize output by averaging off-diagonals.
- **Errors:** `parameterisation_mismatch`, `dimension_mismatch`, `unsupported_feature`.
- **Determinism:** D0.
- **Performance budget:** 10^6 points in under 0.5 s single-threaded [unverified until measured].
- **Crate:** `fid-kunc`.
