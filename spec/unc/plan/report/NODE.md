# UNC.PLAN.REPORT: Measurability evaluation and report

## Purpose

The end-to-end measurability command: for a plan and candidate station sets it runs visibility, predictions and ranking, flags characteristics whose expected U is too large a fraction of their tolerance, and returns a measurability report. Saving the report into the project is a separate journaled W2 command. The report is a planning artifact, never a result.

## Scope

**In:**
- `unc.estimate_measurability@1` (R1): orchestrates `UNC.PLAN.VIS`, `UNC.PLAN.PRED`, `UNC.PLAN.RANK`
- U/T flag with configurable ratio (default 0.25 [unverified])
- `MeasurabilityReport` type and `unc.save_measurability@1` (W2)
- Performance budget for the end-to-end evaluation

**Out:**
- The three steps themselves (owned by their siblings)
- Report layout and printing (owned by `RPT`)

## Requirements

- **REQ-UNC.PLAN.REPORT-001** When `unc.estimate_measurability@1` runs on a plan and candidate station sets, the system shall return a report containing the visibility matrix summary, per-characteristic predictions, the station-set ranking and flags.
- **REQ-UNC.PLAN.REPORT-002** If a characteristic's expected U divided by its tolerance width exceeds the configured ratio (default 0.25), then the report shall flag it `u_over_tolerance_ratio` with the ratio, compared exactly against the decimal threshold.
- **REQ-UNC.PLAN.REPORT-003** The report shall be labelled `prediction` and shall contain no ResultRecord, decision or evidence class.
- **REQ-UNC.PLAN.REPORT-004** When `unc.save_measurability@1` runs, the system shall store the report with its seed, model digests and plan digest and commit one journal event.
- **REQ-UNC.PLAN.REPORT-005** An evaluation of 1,000 targets and 10 candidate stations shall complete in under 5 s on the reference desktop [unverified].

## Acceptance criteria

- **AC-1** Given `fixtures/unc/plan/report/panel_plan.fidproj` (a sheet-metal panel with 40 characteristics and 3 candidate tracker station sets, seed 11), when `fid unc estimate-measurability --plan P-1 --sets S-A,S-B,S-C --seed 11 --json` runs, then the ranking equals `expected_ranking.json` and exactly the characteristics listed in `expected_flags.json` are flagged.
- **AC-2** Given a characteristic with U/T exactly 0.25, then it is not flagged; at the next representable value above, it is flagged.
- **AC-3** Given the report from AC-1, when `fid unc save-measurability --report <digest>` runs, then it is stored and one `unc.save_measurability@1` event is journaled.
- **AC-4** (type safety) Given an attempt to commit a prediction from the report through `unc.propagate_commit@1`, then it fails with `prediction_not_result`.
- **AC-5** (performance) Given `fixtures/unc/plan/report/perf_1000x10.json`, when evaluated on the reference desktop, then it completes in under 5 s (benchmark, reported not gated until measured).
- **AC-6** (replay) Given the journal from AC-1 and AC-3, when replayed in exact mode on the same platform class, then the outcome is `IDENTICAL`.

## Design

- **Registry command(s):** `unc.estimate_measurability@1` (R1; `plan`, `sets: Vec<StationSetId>`, `seed: u64`, `ratio: Decimal = 0.25`; returns `MeasurabilityReport`), `unc.save_measurability@1` (W2; `report_digest`; returns stored ID).
- **Data structures:** `MeasurabilityReport { kind: "prediction", plan_digest, seed, vis_summary, predictions, ranking, flags, model_digests }`.
- **Algorithm:** call the three steps through the bus in order; compute U/T with the tolerance from the plan as exact decimal comparison; assemble; cache by digest for save.
- **Errors:** `plan_not_found`, `set_not_found`, step errors passed through typed.
- **Determinism:** D2 (predictions may use seeded Monte Carlo).
- **Performance budget:** as REQ-UNC.PLAN.REPORT-005.
- **Crate:** `fid-unc-plan`.
