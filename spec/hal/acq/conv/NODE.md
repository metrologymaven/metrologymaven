# HAL.ACQ.CONV: Deterministic conversion of declared encodings to f64 SI values

## Purpose

Converts raw payload arrays from their declared exact encoding (scaled integers or f32 plus offset) into f64 SI values, the same way on every platform. Drivers never convert; the runtime does it here, so replay never depends on a conversion done inside vendor code.

## Scope

**In:**
- `decode(raw, descriptor) -> Vec<f64>` for every numeric type in `EncodingDescriptor`
- Detection of values that cannot be represented exactly before scaling
- Validity-mask handling (masked samples are skipped, never converted to NaN)

**Out:**
- Storing raw batches by digest (owned by `HAL.ACQ.STAMP`)
- Defining the descriptor (owned by `HAL.IDL.UNITS`)
- Frame transforms (owned by `GEO`)

## Requirements

- **REQ-HAL.ACQ.CONV-001** The converter shall compute each value as offset + scale × raw in f64, with the product rounded before the addition (no fused multiply-add), and shall return bit-identical output on every supported platform.
- **REQ-HAL.ACQ.CONV-002** If a raw integer's magnitude exceeds 2^53, then conversion shall fail with `encoding_precision_loss` naming the first index.
- **REQ-HAL.ACQ.CONV-003** If a raw f32 value is NaN or infinite at an index marked valid, then conversion shall fail with `encoding_value_not_finite`.
- **REQ-HAL.ACQ.CONV-004** Samples whose validity-mask bit is false shall be skipped, and the output shall carry the same mask.
- **REQ-HAL.ACQ.CONV-005** If the raw array length differs from the mask length, then conversion shall fail with `encoding_length_mismatch`.

## Acceptance criteria

- **AC-1** Given `fixtures/hal/acq/conv/i32_profile.bin` with descriptor scale 1e-6 m, offset 0.05 m, when converted, then the output digest equals `i32_profile.f64.sha256` on Windows, Linux and macOS.
- **AC-2** Given `fixtures/hal/acq/conv/f32_mixed.bin` with masked NaNs, when converted, then masked entries are skipped and the result matches `f32_mixed.f64.sha256`.
- **AC-3** (error path) Given an i64 raw value of 2^53 + 1, when converted, then it fails with `encoding_precision_loss` at that index.
- **AC-4** (error path) Given an unmasked f32 infinity, when converted, then it fails with `encoding_value_not_finite`.
- **AC-5** (error path) Given 2 000 raw values and a 1 999-bit mask, when converted, then it fails with `encoding_length_mismatch`.
- **AC-6** Given 10 000 profiles of 2 000 i32 points, when converted, then throughput is at least 20 M points per second on reference hardware [unverified until measured].

## Design

- **Registry commands:** none; called by `HAL.ACQ.INGEST` on every batch.
- **Data structures:** `RawArray` (typed slices), `ValidityMask` (bitset), `Decoded { values: Vec<f64>, mask }`.
- **Algorithm:** widen raw to f64 exactly (integers ≤ 2^53, f32 always exact), `let p = scale * x; let v = offset + p;` with FMA contraction disabled; scalar loop with no runtime SIMD dispatch.
- **Errors:** `encoding_precision_loss`, `encoding_value_not_finite`, `encoding_length_mismatch`.
- **Determinism:** D0 (KNP-1 style rules applied: no FMA, no runtime SIMD dispatch).
- **Performance budget:** see AC-6.
- **Crate:** `fid-hal-runtime` (module `conv`).
