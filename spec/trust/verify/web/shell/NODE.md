# TRUST.VERIFY.WEB.SHELL: Static page shell, offline guarantee and report view

## Purpose

The page people actually use: drop a Result Package (and optionally a trust-root, revocation list or kernel file), watch progress, read the verdict and sections, and download the JSON report. It is a set of static files that work from any web server or from local disk, and it provably makes no network request after load.

## Scope

**In:**
- `index.html`, the wasm bundle, generated glue and a stylesheet using design tokens
- Drop zone and file pickers; replay toggle and limits
- Report view (verdict, sections, limitations) and JSON download via a `blob:` URL
- Content security policy and the automated no-network browser test
- Local-disk (`file://`) operation

**Out:**
- Verification logic (`TRUST.VERIFY.WEB.LIB`), streaming (`TRUST.VERIFY.WEB.STREAM`), replay (`TRUST.VERIFY.WEB.WREPLAY`)
- Hosting the page (`OUTR`) and the web release bundle (`ECO.REL.WEB`)

## Requirements

- **REQ-TRUST.VERIFY.WEB.SHELL-001** The page shall carry a content security policy, in a `meta` element, with `connect-src 'none'`, `default-src 'self'`, `script-src 'self' 'wasm-unsafe-eval'`, no remote script, style or font sources, and `form-action 'none'`; the verifier module and the bundled kernel artifact shall therefore be embedded in the static files and instantiated from bytes, never fetched.
- **REQ-TRUST.VERIFY.WEB.SHELL-002** An automated browser test shall load the page, verify every golden package, and fail if any network request is observed after the load event.
- **REQ-TRUST.VERIFY.WEB.SHELL-003** The page shall consist only of static files and shall verify golden packages identically when opened over `http://localhost` and from `file://` in Chromium and Firefox [unverified: `file://` module and worker rules per browser].
- **REQ-TRUST.VERIFY.WEB.SHELL-004** The report view shall show the verdict, each section's status, every listed limitation, and a download of the exact JSON report produced by the library.
- **REQ-TRUST.VERIFY.WEB.SHELL-005** Every string from package content shown on the page shall be inserted as text, never as HTML.
- **REQ-TRUST.VERIFY.WEB.SHELL-006** The page logic shall be Rust compiled to wasm32 with DOM access via `web-sys`, with no hand-written JavaScript beyond generated `wasm-bindgen` glue.

## Acceptance criteria

- **AC-1** Given the built `dist/verify-web/`, when the Playwright test drops each golden package, then the verdict matches the CLI and the request log shows zero requests after load.
- **AC-2** Given `dist/verify-web/index.html` opened via `file://`, then AC-1's verdicts are reproduced.
- **AC-3** (error path) Given a package whose characteristic name contains `<img src=x onerror=...>`, then it is displayed as literal text and no request or script runs.
- **AC-4** Given the downloaded JSON, then it is byte-identical to the library's output for that package.

## Design

- **Registry command(s):** none.
- **Data structures:** view state `{ files, options, progress, report }`.
- **Algorithm:** on drop, hand the `File` to the library (no replay) or to the worker (replay); render the report from its JSON; download through `URL.createObjectURL`.
- **Errors:** display the CLI error code and message.
- **Determinism:** D0 (report bytes); UI rendering is not a value of record.
- **Performance budget:** first paint < 1 s on reference hardware with a cached bundle [unverified].
- **Crate:** `fid-verify-web`, module `shell` plus `web/verify/index.html` and stylesheet built from `UX.TOKENS`.
