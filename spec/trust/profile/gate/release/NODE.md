# TRUST.PROFILE.GATE.RELEASE: Regulated release precondition

## Purpose

A pure precondition, `check_release(snapshot, applied_meanings)`, that any W3 release command calls before it marks a Result Package released. Under Regulated it refuses until every required signature meaning has been applied in the required order; under Lean and Assistive-only it passes when the profile does not require signatures.

## Scope

**In:**
- Comparing the applied signature meaning sequence with the profile's `required_meanings`
- The refusal `profile.signatures_missing` with the missing meanings in order
- Parsing the meaning sequence from the package's signature statements (format published by `TRUST.ESIG.BIND`)

**Out:**
- Verifying signatures cryptographically (`TRUST.SIGN.TROOT`) and sequence integrity (`TRUST.ESIG.MULTI`)
- The release command itself (the ESIG ceremony or a CORE W3 release)

## Requirements

- **REQ-TRUST.PROFILE.GATE.RELEASE-001** While Regulated is active, `check_release` shall return `profile.signatures_missing` listing, in profile order, each required meaning that is not matched in order by the applied sequence.
- **REQ-TRUST.PROFILE.GATE.RELEASE-002** An applied sequence shall satisfy the profile only if the required meanings appear as an ordered subsequence of it; extra tenant meanings in between shall be allowed.
- **REQ-TRUST.PROFILE.GATE.RELEASE-003** When the profile has `release_requires_signatures` false, `check_release` shall return `Ok` whatever the applied sequence.
- **REQ-TRUST.PROFILE.GATE.RELEASE-004** If a signature statement cannot be parsed, then `check_release` shall return `profile.signature_unreadable` and shall not count that statement.

## Acceptance criteria

- **AC-1** Given Regulated with `[AUTHORED, APPROVED]` and applied `[AUTHORED]`, then `profile.signatures_missing` names `APPROVED`; given applied `[]`, it names `AUTHORED, APPROVED` in that order.
- **AC-2** Given applied `[AUTHORED, X_QA_RELEASE, APPROVED]`, then `Ok`; given applied `[APPROVED, AUTHORED]`, then `profile.signatures_missing` names `APPROVED`.
- **AC-3** Given Lean with any sequence, then `Ok`.
- **AC-4** (error path) Given fixture `fixtures/profile/release/bad-statement.json`, then `profile.signature_unreadable`.

## Design

- **Registry command(s):** none; a precondition called by W3 release commands.
- **Data structures:** `AppliedMeanings(Vec<MeaningCode>)` parsed from signature statements in sequence-index order.
- **Algorithm:** greedy ordered-subsequence match of required meanings over the applied list; report unmatched required meanings in order.
- **Errors:** `profile.signatures_missing`, `profile.signature_unreadable`.
- **Determinism:** D0.
- **Performance budget:** trivial (≤ 8 signatures per package, per TRUST.ESIG.MULTI).
- **Crate:** `fid-profile`, module `release` (parses statements by the published schema; no `fid-esig` link).
