# TRUST.CHAIN.CKPT: Checkpoint check and signed-checkpoint verification

## Purpose

Confirms that each checkpoint in a package matches the journal: its head digest equals the recomputed hash of the entry at its index, and, when the checkpoint carries a DSSE signature, that the signature is valid and from a known key. Checkpoints let a verifier trust a segment's start without the whole journal.

## Scope

**In:**
- Parsing `journal/checkpoints/<index>.json` (P0 format: signed linear head per CORE.JRN)
- Matching head digest to the recomputed entry hash at the checkpoint index
- Verifying optional checkpoint signatures via `TRUST.SIGN.TROOT` and reporting fingerprint and trust status
- Result per checkpoint: `MATCH | MISMATCH | OUT_OF_RANGE`, plus signature status

**Out:**
- Creating checkpoints (`CORE.JRN`)
- Merkle (tlog) checkpoints (P1b in CORE.JRN; a later leaf)

## Requirements

- **REQ-TRUST.CHAIN.CKPT-001** For each checkpoint, the checker shall report `MATCH` when its head digest equals the hash of the segment entry at its index, `MISMATCH` when it differs, and `OUT_OF_RANGE` when the index is not in the segment.
- **REQ-TRUST.CHAIN.CKPT-002** When a checkpoint carries a DSSE signature, the checker shall verify it with `TRUST.SIGN.TROOT` and report the fingerprint and status.
- **REQ-TRUST.CHAIN.CKPT-003** If a checkpoint file is malformed or uses an unknown checkpoint format version, then the checker shall report `ckpt.malformed` for that file and continue with the others.

## Acceptance criteria

- **AC-1** Given `fixtures/pkg/golden/points.zip` with one signed checkpoint, when checked with `fixtures/troot/both.json`, then the result is `MATCH` with status `VALID_TRUSTED`.
- **AC-2** (error path) Given `fixtures/chain/ckpt/wrong-head.zip`, then `MISMATCH`; given `fixtures/chain/ckpt/far-index.zip`, then `OUT_OF_RANGE`.
- **AC-3** (error path) Given a checkpoint with a flipped signature byte, then `MATCH` with signature status `INVALID`.
- **AC-4** (error path) Given a checkpoint with format version 99, then `ckpt.malformed` and other checkpoints are still reported.

## Design

- **Registry command(s):** none; called by `verify.check_chain@1`.
- **Data structures:** `Checkpoint { format_version, index: u64, head_sha256, signature: Option<Envelope> }` (assumed CORE.JRN P0 shape); `CheckpointResult { index, status, signature: Option<SigStatus> }`.
- **Algorithm:** lookup entry hash by index from the hash vector built by LINKS; compare; verify signature over the canonical checkpoint body.
- **Errors:** `ckpt.malformed`.
- **Determinism:** D0.
- **Performance budget:** trivial.
- **Crate:** `fid-chain` (module `ckpt`).

## Build prompt

> In crate `fid-chain`, add module `ckpt`. Parse each `journal/checkpoints/<index>.json` (format: `format_version`, `index`, `head_sha256`, optional DSSE `signature`, as published by CORE.JRN for P0 linear heads), compare `head_sha256` with the recomputed entry hash at `index` (`MATCH | MISMATCH | OUT_OF_RANGE`), and verify an attached signature with `fid-sign-core::troot`, reporting fingerprint and status. Malformed or unknown-version files give `ckpt.malformed` and do not stop other checks. Tests: the four acceptance criteria. Constraints: CONSTITUTION §8, D0. If CORE.JRN's checkpoint schema differs from the assumed fields, follow CORE's schema and update the fixtures.
