# KRN.NUM.RED: Fixed-order reductions

## Purpose

Summation, dot product, Euclidean norm and mean whose result depends only on the input values and their order. Every fit, residual statistic and uncertainty sum in the kernel goes through these, so accumulation order can never change a value of record.

## Scope

**In:** `sum`, `dot`, `norm2`, `mean`, `sum_sq` over slices; a fixed partitioning rule; compensated accumulation.
**Out:** matrix products and factorizations (`KRN.NUM.LA`); parallel execution (the kernel is single-threaded in solver paths; any future parallel caller must use these partitions).

## Requirements

- **REQ-KRN.NUM.RED-001** `sum` shall split its input into consecutive blocks of 256 elements, sum each block with Neumaier compensation in index order, and combine the block results by pairwise summation in a fixed binary tree over block index.
- **REQ-KRN.NUM.RED-002** `dot`, `sum_sq`, `norm2` and `mean` shall be defined in terms of `sum` over element-wise products computed without FMA, and `norm2` shall scale by the largest magnitude to avoid overflow.
- **REQ-KRN.NUM.RED-003** Each reduction's result shall depend only on the input values, their order and the length, and shall be bit-identical on x86-64, ARM64 and wasm32.
- **REQ-KRN.NUM.RED-004** If an input contains a NaN or an infinity, or `dot` receives slices of different lengths, then the reduction shall return the typed `NumError`; `mean` of an empty slice shall return `EmptyInput`.

## Acceptance criteria

- **AC-1** Given fixture `fixtures/num/red-illcond-v1` (seeded ill-conditioned sums with condition numbers 1e3 to 1e16 and exact sums known by construction), when `sum` runs, then the relative error is at most 2 ulp [unverified] for condition numbers up to 1e16, and the result digest equals the golden digest.
- **AC-2** Given the same fixture, when run on x86-64, ARM64 and wasm32 under wasmtime, then all result bit patterns are identical.
- **AC-3** Given a 10^6-element slice, when `sum` runs, then the result equals the result of a reference implementation of the same block-and-tree rule written independently in the test (bit-equal).
- **AC-4** (error path) Given a slice with +inf at index 9, when `sum` runs, then it returns `Infinite{index: 9}`; given `dot` on lengths 3 and 4, then it returns `LengthMismatch`.

## Design

- **Registry command(s):** none; module `fid_num::red`.
- **Data structures:** free functions over `&[f64]`; `const BLOCK: usize = 256`.
- **Algorithm:** Neumaier (improved Kahan-Babuska) summation within each block; pairwise combination of `(sum, compensation)` pairs in a fixed tree (left-to-right, recursive halves); `norm2` uses scaled sum of squares (scale = total-order max of |x|) then `fid_num::f::sqrt`.
- **Errors:** `NotANumber`, `Infinite`, `LengthMismatch`, `EmptyInput`.
- **Determinism:** D0.
- **Performance budget:** 1 M-element `sum` < 3 ms on reference hardware [unverified until measured].
- **Crate:** `fid-num` (module `red`).
