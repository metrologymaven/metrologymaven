# KRN.SOLV.CONIC.XTEST: Frozen conic test set and cross-target bit-identity check

## Purpose

Proves that the wrapped solver gives the same bits on every supported target. A frozen set of LP, QP and SOCP problems, shaped like the kernel's minimum-zone, envelope and projection problems plus a few general ones, is solved on x86-64, ARM64 and wasm32, and CI compares a digest of every output bit. A divergence fails the build and names the first differing problem and field.

## Scope

**In:**
- Test set `fixtures/solv/conic-xtest-v1`: at least 150 problems (50 LP, 50 QP, 50 SOCP), seeded synthetic metrology-shaped problems (straightness, flatness and circularity minimum zone, minimum circumscribed and maximum inscribed circles and spheres) plus small generic problems; sizes from 3 to 5000 constraints
- A runner that solves each problem through `KRN.SOLV.CONIC.WRAP` and writes a canonical result list (status, iterations, x, y, s as IEEE-754 hex) and its SHA-256
- The CI comparison across the three targets, with wasm32 run under the pinned runtime
- An accuracy check against offline reference optima

**Out** (and which node owns it instead):
- The solver and wrapper (`KRN.SOLV.CONIC.PATCH`, `KRN.SOLV.CONIC.WRAP`)
- Out-of-kernel cross-check solvers and kernel-wide cross-artifact identity (`KRN.MAN.XART`)

## Requirements

- **REQ-KRN.SOLV.CONIC.XTEST-001** The test set shall contain at least 50 LP, 50 QP and 50 SOCP problems, frozen with a digest, and any change to it shall be a new version of the set.
- **REQ-KRN.SOLV.CONIC.XTEST-002** When CI runs, the runner shall produce on x86-64, ARM64 and wasm32 a canonical result list whose SHA-256 is identical on all three, and shall fail naming the first differing problem and field otherwise.
- **REQ-KRN.SOLV.CONIC.XTEST-003** For every problem the runner shall check the objective against the offline reference within 1e-8 relative [unverified tolerance] and the expected status (solved or the expected infeasibility).
- **REQ-KRN.SOLV.CONIC.XTEST-004** The result list shall be canonical JSON with floats as IEEE-754 hex strings, so equal bits give equal bytes.

## Acceptance criteria

- **AC-1** Given `fixtures/solv/conic-xtest-v1` on x86-64, ARM64 and wasm32 under the pinned wasmtime, when the runner executes, then the three digests are equal and each objective is within tolerance of the reference.
- **AC-2** (error path) Given a test-only patch that perturbs one rounding on one target, when CI compares, then it fails naming the problem ID and field.
- **AC-3** Given the infeasible problems in the set, then each yields its expected `SolverError` cause on all targets.

## Design

- **Registry command(s):** none; test binary `conic-xtest` in `fid-solv` (dev target).
- **Data structures:** problem files in a simple canonical JSON form (P, q, A, b, cones, expected status, reference objective); result list `[{ id, status, iterations, x: [hex], y: [hex], s: [hex] }]`.
- **Algorithm:** generate problems with a committed seeded script; solve in ID order; serialise; hash; compare in a CI job that collects the three digests.
- **Errors:** test failures only.
- **Determinism:** D0 is what it checks.
- **Performance budget:** whole set < 60 s per target [unverified until measured].
- **Crate:** `fid-solv` (dev target).

## Test fixtures

`fixtures/solv/conic-xtest-v1`: generated by a committed seeded script; reference optima computed offline with an independent solver at high precision; CC-BY-4.0.
