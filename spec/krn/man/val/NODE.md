# KRN.MAN.VAL: Validation harness and per-release report

## Purpose

Turns reference datasets into published evidence. For every release, the harness runs each least-squares and minimum-zone algorithm on the frozen PTB TraCIM and NIST reference sets (and other reference suites), applies each set's pass criteria, writes the pass or fail status per algorithm and primitive into the spec cards' validation evidence and a release report, and runs out-of-kernel cross-check solvers. The report is generated by CI and never hand-edited.

## Scope

**In:**
- A harness that maps each reference case to a kernel call and compares outputs with reference results under the set's pass criteria
- Pass criteria as data per reference set (for example, 1/10 of the TraCIM default MPE as the internal limit [unverified])
- Out-of-kernel cross-checks in CI (for example an independent LP solver) that never link into the kernel
- The per-release validation report (canonical JSON plus a generated human-readable page) and its digest for the manifest
- Feeding validation evidence into spec cards

**Out** (and which node owns it instead):
- The datasets, synthetic generators and the TraCIM client (`UNC.RDL`), consumed at test time only
- Algorithms under test (`KRN.LSQ`, `KRN.MZ`, `KRN.ENV`)
- Publishing the report on the website (`OUTR`) and in release bundles (`ECO`)

## Requirements

- **REQ-KRN.MAN.VAL-001** For every release, the harness shall run each least-squares and minimum-zone algorithm on every case of the frozen PTB TraCIM and NIST reference sets that matches its primitive, through the WASM reference artifact.
- **REQ-KRN.MAN.VAL-002** The harness shall apply pass criteria held as versioned data per reference set and record, per algorithm and primitive, the number of cases passed, failed and not run, and the worst deviation per parameter.
- **REQ-KRN.MAN.VAL-003** The per-release report shall be generated by CI as canonical JSON with a digest, shall be reproducible from the same inputs, and CI shall fail if a committed copy differs from the regenerated one.
- **REQ-KRN.MAN.VAL-004** When an algorithm has a spec card, the harness shall write its validation evidence (reference set, version, pass counts, report digest) into the card's evidence field for the release.
- **REQ-KRN.MAN.VAL-005** Out-of-kernel cross-check solvers shall run only in CI, and a disagreement beyond the set's tolerance shall fail CI with the case identifier.

## Interfaces

- **Offers:** the validation report and digest (to `KRN.MAN.MANI`, `ECO`, `OUTR`); validation evidence for spec cards (`KRN.MAN.CARD`).
- **Consumes:** `KRN.MAN.KCI`, `KRN.MAN.CARD`, `KRN.MAN.XART` (artifact runner); artifacts read at test time (`uses_artifacts`): the frozen RDL release and its record format (`UNC.RDL.FREEZE`, `UNC.RDL.FORMAT`) and the WASM reference artifact (`KRN.MAN.WASM`).

## Decomposition hints

MAP (case-to-call mapping per reference set), CRIT (pass criteria as data), RPT (report generation and regeneration check), XCHK (out-of-kernel cross-check runners), EVID (spec-card evidence update).

## Open questions

- TraCIM test-result redistribution terms are unverified; the public report may need to show pass status without reference values.
- The internal pass limit (1/10 of the TraCIM default MPE) is from the parent's requirements and is [unverified] until the TraCIM published test conditions are read.

- The harness is test tooling (CONSTITUTION §2.1): its children read reference data and the WASM artifact as artifacts and use only the `KRN.MAN.XART` runner and `KRN.MAN.KCI` hashing as code; no child links a fit crate directly.
