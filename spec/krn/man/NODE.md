# KRN.MAN: Kernel identity, WASM reference artifact and validation evidence

## Purpose

Makes the kernel identifiable and its results reproducible and checkable: the kernel call interface, the algorithm ID and spec-card registry, the kernel manifest and its digest, the byte-identical WASM reference artifact, the cross-host bit-identity gate, and the per-release validation report against reference datasets. Fit subsystems produce algorithms; this subsystem turns them into identified, evidenced releases. It owns no geometry.

## Scope

**In:**
- Kernel call interface: one pure `evaluate(call) -> result` entry point that names an algorithm ID, typed parameters, a seed and input bytes with claimed digests; it re-hashes inputs and hashes outputs itself
- Algorithm ID scheme `<module>.<feature>.<method>@<semver>` and the spec-card format (method, applicability limits, references by designator and clause, determinism class, known failure modes, validation evidence)
- Spec-card registry: every registered algorithm has a card, and cards are served as data
- Kernel manifest (name, semver, numeric profile, source and lockfile digests, toolchain, artifacts, algorithms with per-algorithm implementation digests, reference-set digests) and its RFC 8785 + SHA-256 digest
- WASM reference build (wasm32 target, empty or allowlisted import section, pinned runtime configuration)
- Native performance builds and the cross-artifact bit-identity measurement and gate
- Reproducible-build settings and an independent rebuild check
- The validation harness: runs the frozen reference set on every artifact, applies pass criteria, and publishes per-release pass/fail per algorithm and primitive
- Out-of-kernel cross-check runs in CI (for example an independent LP solver), which never link into the kernel
- Semver rules for the kernel (patch = bit-identical on the frozen reference set)

**Out** (and which node owns it instead):
- The reference datasets, synthetic generators and the TraCIM client (`UNC`, its RDL)
- The KNP-1 lint and `fid-num` (`KRN.NUM`)
- The algorithms the cards describe (`KRN.LSQ`, `KRN.MZ`, `KRN.ENV`, `KRN.CONS`, `KRN.OUT`)
- Verifier replay using the WASM artifact and result signing (`TRUST`)
- Release channels, installers and signed releases (`ECO`)
- Journal hashing and the command bus that calls the kernel (`CORE`)

## Requirements

- **REQ-KRN.MAN-001** The kernel shall expose exactly one call entry point that takes an algorithm ID, typed parameters, an optional seed and input bytes with claimed digests, and returns a result envelope or a typed error.
- **REQ-KRN.MAN-002** If the digest the kernel computes for an input differs from the claimed digest, then the call shall return a typed `digest_mismatch` error and compute nothing.
- **REQ-KRN.MAN-003** Every algorithm registered in the kernel shall have an ID of the form `<module>.<feature>.<method>@<semver>` and a spec card with method, applicability limits, references by designator, edition and clause, determinism class and validation evidence, and CI shall fail on any algorithm without one.
- **REQ-KRN.MAN-004** The kernel manifest shall list the numeric profile, source-tree, lockfile and toolchain digests, every artifact with its target and hash, every algorithm with its implementation digest, and the frozen reference-set digests, and its digest shall be SHA-256 over its RFC 8785 canonical JSON.
- **REQ-KRN.MAN-005** The kernel shall build as a wasm32 reference artifact whose import section is empty or contains only allowlisted imports, and CI shall fail on any other import.
- **REQ-KRN.MAN-006** On the frozen reference dataset release, the WASM reference artifact shall produce bit-identical output digests on Windows, Linux and macOS hosts on x86-64 and ARM64.
- **REQ-KRN.MAN-007** For every release candidate, CI shall measure and publish whether each native artifact's output digests on the frozen reference set equal the WASM artifact's.
- **REQ-KRN.MAN-008** For every release, the harness shall publish the pass or fail status of each least-squares and minimum-zone algorithm on the public PTB TraCIM and NIST reference datasets, per primitive, generated by CI and never hand-edited.
- **REQ-KRN.MAN-009** Two independent builds of the same kernel source and lockfile shall produce byte-identical WASM artifacts.
- **REQ-KRN.MAN-010** When a kernel patch release changes any output digest on the frozen reference set, CI shall fail the release.

## Interfaces

- **Offers:** the kernel call interface; `KernelManifest` and its digest (recorded in every ResultRecord); the spec-card registry (served as data to `AUTO` and `TRUST`); the WASM reference artifact for `TRUST` verifier replay; the per-release validation report for `ECO` and `OUTR`.
- **Consumes:** `KRN.NUM` (facade self-test digest); frozen reference sets from `UNC` at test time only (no build dependency, so the kernel layering holds).

## Decomposition hints

KCI (call interface and digest checks), CARD (algorithm IDs, spec-card format and registry), MANI (manifest and digest), WASM (reference build and import check), XART (native builds and bit-identity measurement), REPRO (reproducible build and independent rebuild), VAL (validation harness and per-release report).

## Open questions

- Native artifacts may compute values of record only after a later phase gate (the concept baseline says from P1b). That is a phase-policy choice for the steering group; this node only measures and reports.
- TraCIM test-result redistribution terms are unverified (see UNC's open question on dataset licences).
