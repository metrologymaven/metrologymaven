# IO.QIF.XML.PARSE: Hardened streaming XML reader

## Purpose

The one XML pull reader used by every IO component that reads XML (QIF documents, XSDs, workbook parts): it refuses DTDs, entity declarations, external entities and XInclude before resolving anything, runs under the IO limit harness with depth and attribute caps, and reports every position as line and column. Other IO nodes reuse it instead of configuring their own parser.

## Scope

**In:**
- Pull events: start, end, text, CDATA, comment, processing instruction (PIs other than the XML declaration reported, never executed)
- Namespace resolution with in-scope declaration tracking (needed for extension pass-through)
- Encodings: UTF-8 (with or without BOM) and UTF-16 with BOM; others rejected
- Limits: element depth 64, attributes per element 256, name length 1,024 bytes, text node 64 MiB [unverified: tune on corpus], plus the `IO.REG.LIMITS` budget
- Byte spans per event so extension content can be captured byte-faithfully

**Out:**
- Schema validation (`IO.QIF.XML.VALID`)
- Binding events into model types (generated by `IO.QIF.GEN.RUST`)

## Requirements

- **REQ-IO.QIF.XML.PARSE-001** If the input contains a DOCTYPE, an entity declaration, a reference to an entity other than the five predefined ones, or an element in the XInclude namespace, then the reader shall fail with `xml_forbidden_construct` at that position before resolving it.
- **REQ-IO.QIF.XML.PARSE-002** If element depth exceeds 64 or an element has more than 256 attributes, then the reader shall fail with `limit_exceeded` naming the limit.
- **REQ-IO.QIF.XML.PARSE-003** Every event and every error shall carry byte offset, line and column.
- **REQ-IO.QIF.XML.PARSE-004** If the declared or detected encoding is not UTF-8 or UTF-16 with BOM, then the reader shall fail with `xml_encoding_unsupported`.
- **REQ-IO.QIF.XML.PARSE-005** On any byte sequence the reader shall return events or a typed error and shall not panic, abort or loop without bound, verified by a fuzz target run in CI.
- **REQ-IO.QIF.XML.PARSE-006** Each element event shall expose the in-scope namespace declarations and the byte span of the element, so callers can copy a subtree verbatim.

## Acceptance criteria

- **AC-1** Given `fixtures/io/qif/xml/parse/xxe.xml` (external entity), `doctype.xml`, `billion_laughs.xml` and `xinclude.xml`, then each fails `xml_forbidden_construct` at the construct's line.
- **AC-2** (error path) Given `fixtures/io/qif/xml/parse/deep65.xml`, then the reader fails `limit_exceeded` (depth 64).
- **AC-3** (error path) Given an element with 257 attributes, then `limit_exceeded` (attributes 256).
- **AC-4** Given `fixtures/io/qif/xml/parse/utf16.xml` with BOM, then events equal those of the UTF-8 twin; given `latin1.xml` declaring ISO-8859-1, then `xml_encoding_unsupported`.
- **AC-5** Given the fuzz target and the hostile corpus from `IO.CORP`, when run for the CI time budget, then no panic, abort or timeout occurs.
- **AC-6** Given `fixtures/io/qif/xml/parse/ns.xml`, then the span of a nested element copied verbatim and re-parsed with its reported namespace declarations yields the same events.

## Design

- **Registry commands:** none (library).
- **Data structures:** `XmlEvent { kind, name: QName, attrs: Vec<Attr>, ns_scope: NsScopeRef, span: Range<u64>, pos: Position }`; text as `UntrustedText` slices.
- **Algorithm:** pull parser over `BoundedSource` with explicit depth counter; DTD and entity tokens rejected at the lexer; namespace stack as a Vec of frames. Build on a vetted pure-Rust tokenizer with entity expansion disabled, or a small in-house lexer [unverified: crate choice and D-001 allowlist].
- **Errors:** `xml_forbidden_construct`, `xml_encoding_unsupported`, `limit_exceeded`, `malformed{at}`, `truncated_file{at}`.
- **Determinism:** D0.
- **Performance budget:** ≥ 200 MB/s event throughput [unverified until measured].
- **Crate:** `fid-xml` (small shared crate used by `fid-qif`, `fid-qif-gen` and `fid-io-res`).

## Test fixtures

Add a cargo-fuzz target. CONSTITUTION §8: no panics, no unwrap, no `unsafe`; no unbounded recursion. Tests AC-1..AC-6.
