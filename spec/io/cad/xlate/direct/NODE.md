# IO.CAD.XLATE.DIRECT: Direct translator output validation and commit

## Purpose

For translators whose output kind is `direct`, accepts B-rep, assembly and PMI records instead of STEP bytes, using the same record schema as the first-party CAD worker (`IO.CAD.WORKER.PROTO`), and puts them through the same validation and rebuild as first-party STEP output before anything is staged. A translator never writes into the document directly.

## Scope

**In:**
- Record schema reuse: translators emit `fid-cad-proto` `Record` batches through the plugin ABI
- Validation: protocol validation, GEO.CAD.TOPO validation of rebuilt bodies, QIF type invariants for PMI records; failure → `plugin_output_invalid` naming the first bad record
- Source references: translator-supplied native IDs kept as imported IDs (untrusted text); document IDs as UUIDv5 from (native blob digest, record index)
- Staging for `IO.CAD.XLATE.BRIDGE` to commit

**Out:**
- The command and provenance (`IO.CAD.XLATE.BRIDGE`)
- Plugin host and ABI (`IO.REG.PLUGIN`)

## Requirements

- **REQ-IO.CAD.XLATE.DIRECT-001** Direct translator output shall be accepted only as `fid-cad-proto` records and shall pass the same protocol and topology validation as first-party worker output before staging.
- **REQ-IO.CAD.XLATE.DIRECT-002** If any record fails validation, then the import shall fail with `plugin_output_invalid` naming the record index and reason, and nothing shall be staged.
- **REQ-IO.CAD.XLATE.DIRECT-003** Translator-supplied identifiers shall be kept as imported IDs typed as untrusted text, and document IDs shall be derived deterministically from the native blob digest and record index.

## Acceptance criteria

- **AC-1** Given the fake translator in `direct` mode returning the cube's records (`fixtures/io/cad/xlate/direct/cube_records.bin`), when validated and staged, then one body with 6 faces is staged with UUIDv5 IDs.
- **AC-2** (error path) Given records with a face referencing a missing loop, then `plugin_output_invalid{record: n, reason: invalid_message}` and nothing is staged.
- **AC-3** (error path) Given records describing an open shell flagged closed, then GEO validation defects are listed and the body is staged with them reported (no repair), matching first-party STEP behaviour.
- **AC-4** Staging the same records twice gives identical IDs.

## Design

- **Registry commands:** none (library used by `import.cad_native@1`).
- **Data structures:** reuses `fid-cad-proto::Record`; `DirectStage { bodies, instances, pmi, defects }`.
- **Algorithm:** decode with `ProtoLimits` → validate → rebuild via the same rebuild function as `IO.CAD.STEP.CMD` (exposed by `fid-io-cad`) → stage.
- **Errors:** `plugin_output_invalid`, `limit_exceeded`.
- **Determinism:** D0 given the records.
- **Performance budget:** as first-party rebuild.
- **Crate:** `fid-io-cad-xlate`.
