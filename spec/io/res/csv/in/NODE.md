# IO.RES.CSV.IN: Result table import through a column map

## Purpose

`import.results_csv@1` imports a table of characteristic results (from a CMM export, an arm, a spreadsheet of hand-gauge readings) as transcribed results. A column map is mandatory and journaled by ID, version and digest. The source is a CSV or TSV file, or one sheet of a workbook read by the bounded workbook reader, so result tables kept in spreadsheets use the same map rules.

## Scope

**In:**
- `import.results_csv@1` (W2) on the import skeleton; params include `map` (built-in ID or a root handle to a user map) and `sheet` for workbook sources
- Bounded line reading (64 KiB per line) with the map's dialect; workbook sheets through `IO.RES.CSV.XLSX` as a cell grid
- Required-column checks per row; optional `skip_bad_rows`
- Row → `SourceRow` → `transcribe`; linking by characteristic ID, then name

**Out:**
- Map schema and validation (`IO.RES.CSV.MAP`); workbook decoding (`IO.RES.CSV.XLSX`)
- Export (`IO.RES.CSV.OUT`)

## Requirements

- **REQ-IO.RES.CSV.IN-001** The command shall require a column map and fail with `colmap_required` when none is given, and on success the journal event shall hold the map's ID, version and SHA-256.
- **REQ-IO.RES.CSV.IN-002** If a row lacks a value in a column the map marks required, then the import shall fail with `malformed` naming the line (or sheet and cell) and column, unless `skip_bad_rows` is set, in which case the row is dropped and listed in the report.
- **REQ-IO.RES.CSV.IN-003** Every mapped value shall become a transcribed result through `IO.RES.TRANS.MODEL`, with its decimal text kept exactly as read (after decimal-comma normalisation recorded in the report).
- **REQ-IO.RES.CSV.IN-004** The command shall require `source_software` when the map has no source-software column, and fail with `source_software_required` otherwise.
- **REQ-IO.RES.CSV.IN-005** When the source is a workbook, the command shall read only the named sheet, use cached cell values, never evaluate formulas, and report `formula_cached_value_used` for every formula cell it read.

## Acceptance criteria

- **AC-1** Given `fixtures/io/res/csv/in/cmm_export.csv` (semicolon, decimal comma, 40 rows) and map `user_map.json`, when `fid import results-csv --source root://in/cmm_export.csv --map root://in/user_map.json --source-software "VendorC 2" --json` runs, then 40 transcribed results are committed and the journal event holds the map ID, version and digest.
- **AC-2** (error path) Given no `--map`, then `colmap_required`.
- **AC-3** (error path) Given `missing_actual.csv` with an empty required `actual` on line 7, then `malformed` naming line 7 and column `actual`; with `--skip-bad-rows`, 39 results and one dropped row in the report.
- **AC-4** Given `readings.xlsx` sheet `Data` with the same table and two formula cells, when imported with `--sheet Data`, then results equal AC-1's and the report has two `formula_cached_value_used` warnings.
- **AC-5** Given value text `0,0100` in a decimal-comma dialect, then the stored text is `0.0100`.
- **AC-6** (replay) Given AC-1's journal, when replayed exactly, then `IDENTICAL`.

## Design

- **Registry command:** `import.results_csv@1` W2; params `source: RootHandle`, `map: ColMapRef`, `sheet?: String`, `source_software?: String`, `source_version?: String`, `skip_bad_rows: bool = false`, `create_missing: bool = false`, `run?: RunId`, `stage?: StageId`, `dry_run: bool = false`; result `ImportReport` plus `{ record, results, dropped }`.
- **Data structures:** `RowSource` trait implemented for delimited text and workbook sheets.
- **Algorithm:** load map → choose row source (by detected format) → per row: required check, decimal normalisation (`,` → `.` only in decimal fields), `SourceRow` → `transcribe` → link → stage.
- **Errors:** `colmap_required`, `colmap_invalid`, `malformed`, `source_software_required`, `limit_exceeded`, envelope errors.
- **Determinism:** D0.
- **Performance budget:** 10^5 rows in < 2 s [unverified until measured].
- **Crate:** `fid-io-res` (module `csv::in`).
