# IO.CLOUD.E57.READ: E57 import command

## Purpose

`import.cloud_e57@1` imports every scan of an E57 file as its own point set in a frame holding that scan's pose, streaming points through `PointSink`. It keeps f64 coordinates exact, converts spherical coordinates through the `fid-num` facade and records that it did, maps intensity, colour and grid indices to point attributes, and skips and counts invalid points.

## Scope

**In:**
- `import.cloud_e57@1` (W2) on the `IO.REG.ENV` skeleton: `source`, `scans?` (subset by index or guid), `attributes?`, `stage?`, `dry_run?`, `limits?`
- E57 format descriptor (signature at offset 0, extension `.e57`)
- One point set per scan; frame from the pose (quaternion normalised with fixed-order arithmetic; deviation > 1e-6 warned, > 1e-3 fails `malformed`)
- Cartesian fields as stored; spherical (range, azimuth, elevation) converted via `fid-num` sin/cos, with `converted_from: spherical` in provenance
- Attributes: intensity (with its limits), colour (with its limits), row and column index, timestamp; invalid-state flags: invalid points skipped and counted per scan
- Units: metres as the format defines [unverified]; per-field source precision recorded
- Import report: scans, points per scan, skipped invalid, images counted, precision per field

**Out:**
- Layers below (`.PHYS`, `.XML`, `.CVEC`), export (`IO.CLOUD.E57.WRITE`)
- Registration between scans (SCAN)

## Requirements

- **REQ-IO.CLOUD.E57.READ-001** When an E57 file with several scans is imported, the command shall create one point set per selected scan, each in its own frame equal to the scan's pose, with coordinates stored as written.
- **REQ-IO.CLOUD.E57.READ-002** Cartesian f64 coordinates shall be imported bit-identically, and every point set shall record its per-axis source precision.
- **REQ-IO.CLOUD.E57.READ-003** Spherical coordinates shall be converted to Cartesian through the `fid-num` facade, and the provenance shall record `converted_from: spherical`.
- **REQ-IO.CLOUD.E57.READ-004** Points flagged invalid shall be skipped and counted per scan in the import report.
- **REQ-IO.CLOUD.E57.READ-005** If a pose quaternion's norm differs from 1 by more than 1e-3, then the import shall fail with `malformed{reason: pose_not_unit}` naming the scan.

## Design

- **Registry commands:** `import.cloud_e57@1` (W2; params above; result `ImportReport` with an E57 section). CLI `fid import cloud-e57`, MCP `import_cloud_e57`.
- **Algorithm:** open (PHYS) → parse XML → per selected scan: frame from pose → `CvecReader` batches → field mapping → `PointSink` → one transaction.
- **Errors:** `checksum_mismatch`, `malformed`, `truncated_file`, `limit_exceeded`, `cancelled`, envelope errors.
- **Determinism:** D0 (spherical conversion via `fid-num`, KNP-1).
- **Performance budget:** 10^8 points in < 120 s and < 4 GiB peak resident memory [unverified until measured].
- **Crate:** `fid-io-cloud` (using `fid-io-e57`).
