# OUTR.CONTENT.MIG.GOM: Migration guide for ZEISS INSPECT (GOM) users

## Purpose

A written guide for people who do scan-to-CAD inspection in ZEISS INSPECT Optical 3D (formerly GOM Inspect) and want to do the same jobs in the Inspect app. It walks the main workflow (import, pre-alignment, best-fit, surface comparison, sections, GD&T, report) in our own words, embeds the generated mapping table for the `seeds/gom-inspect.md` inventory, and is built on one published example project and journal. It is a writing task checked by existing tooling.

## Scope

**In:** the guide text; the embedded mapping table regenerated by `mig-map`; the example project and journal the guide uses, contributed through ECO's example-project process; our own screenshots made with `capture.take_screenshot`.
**Out:** the table generator (`OUTR.CONTENT.MIG.MAP`); the PolyWorks guide (`OUTR.CONTENT.MIG.PW`); videos (`OUTR.CONTENT.VIDEO`); benchmark comparisons with the incumbent (`OUTR.BENCH`).

## Requirements

- **REQ-OUTR.CONTENT.MIG.GOM-001** The guide shall embed the `mig-map` table for `seeds/gom-inspect.md`, and `mig-map check` shall pass on it against the release named in its manifest.
- **REQ-OUTR.CONTENT.MIG.GOM-002** The guide shall have one section per workflow stage (import, alignment, comparison, sections, GD&T evaluation, reporting), each naming our commands for the stage or linking the gap rows of the table.
- **REQ-OUTR.CONTENT.MIG.GOM-003** The guide shall contain no text, screenshot, icon or menu graphic taken from the incumbent's software or documentation, and every image in it shall be a file produced by our `capture.*` commands.
- **REQ-OUTR.CONTENT.MIG.GOM-004** The guide shall state near its top that the seed inventory rows are unverified until confirmed by users of the product.
- **REQ-OUTR.CONTENT.MIG.GOM-005** The guide's manifest shall name its example project, journal, journal digest and verified release, and `content-check` shall pass on it.
- **REQ-OUTR.CONTENT.MIG.GOM-006** Before publication, the guide shall have a passing OUTR.BRAND.REVIEW record by a reviewer other than its author.

## Acceptance criteria

- **AC-1** Given the guide source and fixture `fixtures/outr/mig/release` (the trace and coverage files of the targeted release), when `fid-outreach mig-map check` runs, then it exits 0.
- **AC-2** Given the guide source, when `fid-outreach content-check --root <guide dir> --rules claim-rules.toml` runs, then it exits 0.
- **AC-3** Given the guide's example project and journal, when the release's replay runs in exact mode, then the outcome is `IDENTICAL`.
- **AC-4** Given the guide, when a test lists its headings, then it finds the six stage sections of REQ-002 and the unverified-rows notice in the first 20 lines.
- **AC-5** Given the guide's images folder, when a test compares each image's SHA-256 with the digests in the example journal's capture entries, then every image matches one entry.
- **AC-6** Given the review record for the guide, when `fid-outreach review-gate` runs with the guide author, then it exits 0.

## Design

- **Registry command(s):** none; content checked by `mig-map`, `content-check` and `review-gate`.
- **Files:** `content/migration/gom-inspect/guide.md` (manifest with `kind: migration`, `inventory: gom-inspect.md`), `images/` (exported captures), the example project ID from the ECO example-project index.
- **Workflow source:** seed rows of `seeds/gom-inspect.md` in the areas GOM.IMP, GOM.CAD, GOM.ALN, GOM.SRF, GOM.DIM, GOM.GDT and GOM.RPT (sections are under GOM.DIM or GOM.SRF [unverified]); the table still lists every in-scope row.
- **Determinism:** D0 for the checks; the text is static.
- **Crate:** none (content); checks run from `fid-outreach`.

## Test fixtures

The example project and journal from ECO's example-project set for Inspect (built on a public or CC-licensed scan and CAD pair); the release's `trace.json` and `generated/COVERAGE.md`. No incumbent files are used or shipped.
