# CMM.COLL.FIXT: Fixture models and nominal part placement

## Purpose

Defines the setup on the table: fixture models built from primitives or mesh references, and the nominal placement of the part (its CAD or mesh model and pose in the machine frame). Their digests are the run ticket's `setup.fixture` and `setup.part_placement`. The placement is nominal: the true placement is known only after alignment, which is why `CMM.EXEC` runs a placement check each cycle.

## Scope

**In:**
- `FixtureModel` (ID, version, digest, bodies as boxes, cylinders or mesh digests, pose in machine frame)
- `PartPlacement` (ID, version, digest, part model digest, pose in machine frame, optional fixture reference)
- Validation of poses (finite, proper rotation) and bodies
- `cmm.define_fixture@1` and `cmm.set_part_placement@1` (both W2)

**Out** (and which node owns it instead):
- Importing fixture and part CAD or meshes (owned by `IO` and `GEO`)
- Measured placement (alignment) (owned by `ALN`)
- Collision queries (owned by `CMM.COLL.CHECK`)

## Requirements

- **REQ-CMM.COLL.FIXT-001** The system shall represent a fixture model as a versioned entity with bodies (box, cylinder, or mesh by digest) and a pose in the machine frame, and a part placement as a versioned entity referencing a part model digest, a pose and an optional fixture.
- **REQ-CMM.COLL.FIXT-002** If a pose has a non-finite element or a rotation part that deviates from orthonormal with determinant +1 by more than 1e-9, then the system shall reject it with `POSE_INVALID`.
- **REQ-CMM.COLL.FIXT-003** If a referenced mesh or part model digest is not present in the project store, then the system shall reject the entity with `MODEL_REF_MISSING`.
- **REQ-CMM.COLL.FIXT-004** The system shall compute fixture and placement digests as SHA-256 over RFC 8785 canonical JSON of all fields except display names, so any geometry, pose or reference change changes the digest.

## Acceptance criteria

- **AC-1** Given fixture `fixtures/cmm/coll/vise_fixture.json` (vise as three boxes), when `fid cmm define-fixture --file vise_fixture.json --json` runs, then the fixture is created with the fixture file's `expected_digest`.
- **AC-2** Given the AC-1 fixture and part mesh `fixtures/cmm/coll/block_part.stl` (digest in `block_part.digest`), when `fid cmm set-part-placement --part <digest> --pose block_pose.json --fixture <id> --json` runs, then a placement is created with `expected_placement_digest`.
- **AC-3** Given AC-2 with the pose translated by 0.1 mm, when set as an edit, then a new version with a different digest is created.
- **AC-4** (error path) Given a pose whose rotation has determinant −1, when set, then it fails with `POSE_INVALID` and journals nothing.
- **AC-5** (error path) Given an unknown part digest, when set, then it fails with `MODEL_REF_MISSING`.
- **AC-6** (replay) Given the journal from AC-1 and AC-2, when replayed in exact mode, then the outcome is `IDENTICAL`.

## Design

- **Registry commands:** `cmm.define_fixture@1` (W2; params `FixtureModelInput`, `edit_of`; result `{fixture_id, version, digest}`); `cmm.set_part_placement@1` (W2; params `part_model: Digest`, `pose: Pose`, `fixture: Option<FixtureId>`, `edit_of`; result `{placement_id, version, digest}`).
- **Data structures:** `FixtureModel { id, version, name: UntrustedText, pose, bodies: Vec<Body>, digest }`; `PartPlacement { id, version, part_model, pose, fixture, digest }`; `Body` shared with `CMM.COLL.MACH`.
- **Algorithm:** validation; orthonormality via fixed-order dot products; digest via JCS.
- **Errors:** `POSE_INVALID`, `MODEL_REF_MISSING`, `FIXTURE_BODY_INVALID`, `FIXTURE_NOT_FOUND`.
- **Determinism:** D0.
- **Crate:** `fid-cmm-coll`.

> Constraints: no FMA; NaN is an error; no panic, no `unsafe`, no `unwrap`/`expect`; determinism D0.
