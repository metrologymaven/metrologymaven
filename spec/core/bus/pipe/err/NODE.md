# CORE.BUS.PIPE.ERR: Closed bus error code set

## Purpose

One closed set of stable error codes, with reasons, that every surface reports the same way: the CLI maps codes to exit codes, MCP to tool errors, Python to exception classes. The set is published as a versioned file that the registry manifest embeds by digest, so surfaces are generated from it.

## Scope

**In:** `BusError` enum, code and reason strings, the published `bus-errors.json` file and its digest, the rule that codes are never renamed or reused.
**Out:** embedding the digest in the manifest (`CORE.REG.MAN` reads the file); surface mappings to exit codes and exceptions (`AUTO`).

## Requirements

- **REQ-CORE.BUS.PIPE.ERR-001** The bus shall define exactly the error codes `validation`, `policy`, `precondition`, `conflict`, `not_found`, `hidden_command`, `undeclared_effect`, `cancelled`, `unauthenticated`, `idempotency_mismatch`, `upgrade_refused` and `internal`, each with a closed list of reason strings.
- **REQ-CORE.BUS.PIPE.ERR-002** The bus shall publish the codes and reasons as `bus-errors.json` (schema version 1) in canonical JSON with a `sha256:` digest.
- **REQ-CORE.BUS.PIPE.ERR-003** If a code or reason present in the previous published version is missing or renamed, then the build check shall fail; new codes and reasons may only be added.
- **REQ-CORE.BUS.PIPE.ERR-004** Every `BusError` value shall serialise to `{code, reason, detail}` where `detail` is untrusted text that surfaces display but never parse.

## Acceptance criteria

- **AC-1** Given the crate, when `bus-errors.json` is generated, then it lists exactly the twelve codes of REQ-001 and its digest equals the committed `fixtures/core/bus/pipe/err/bus-errors.v1.digest`.
- **AC-2** (error path) Given a branch that renames `conflict` to `head_conflict`, when the compatibility check runs against `fixtures/core/bus/pipe/err/bus-errors.v1.json`, then it fails naming `conflict`.
- **AC-3** Given each code, when serialised, then the JSON validates against `bus-error.schema.json`.

## Design

- **Registry command(s):** none.
- **Data structures:** `enum BusError { Validation(Reason, Detail), Policy(..), ... , Internal(..) }`; `Reason` enums per code; `Detail = Untrusted<String>` limited to 2,000 characters.
- **Algorithm:** a generator writes the file through `fid-canon`; a test compares against the previous version and fails on removal.
- **Errors:** not applicable.
- **Determinism:** D0.
- **Performance budget:** not applicable.
- **Crate:** `fid-bus` (module `error`).
