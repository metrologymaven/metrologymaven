# CORE.JRN.BR.DIFF: Entity and result diff between branches

## Purpose

Answers "what would promoting this branch change?" without re-executing anything. DIFF finds the common ancestor of two branch heads on the logical DAG, folds each side's entries into a map from stable entity ID to the last output digest, and lists entities added, removed and changed, with old and new digests. The result type is the semantic and result layer of the VIZ Proposal Inbox diff.

## Scope

**In:** `journal.diff_branch@1`; common-ancestor search on the logical DAG; per-entity fold of output digests from entry headers; added, removed and changed sets; the command IDs that touched each entity; `branch-diff.schema.json`.
**Out:** value-level deltas between results (`CORE.RPL.XVER`-style comparison); rendering (`VIZ.INBOX`); promotion (`CORE.JRN.BR.PROMO`).

## Requirements

- **REQ-CORE.JRN.BR.DIFF-001** When `journal.diff_branch@1` runs with a source and a target branch, the journal shall find their nearest common ancestor on the logical DAG and report its hash.
- **REQ-CORE.JRN.BR.DIFF-002** The diff shall list entities added on the source, removed on the source and changed on either side, each keyed by stable entity ID, sorted by ID.
- **REQ-CORE.JRN.BR.DIFF-003** For each changed entity, the diff shall give the target's and the source's last output digest and the command IDs that changed it on each side since the ancestor.
- **REQ-CORE.JRN.BR.DIFF-004** When an entity changed on both sides to different digests, the diff shall flag it `conflict`.
- **REQ-CORE.JRN.BR.DIFF-005** The diff shall be computed from entry headers only, so it works when payloads have been removed, and shall be side-effect class R0.

## Acceptance criteria

- **AC-1** Given fixture `fixtures/core/jrn/br/diff/fork` (ancestor with entities e1..e5; source adds e6, removes e2, changes e3; target changes e4 and e3 differently), when `fid journal diff-branch --source s --target main --json` runs, then the result lists added [e6], removed [e2], changed [e3 (conflict), e4], with digests, and validates against `branch-diff.schema.json`.
- **AC-2** Given two branches with no changes since the ancestor, then all lists are empty.
- **AC-3** Given the fork fixture with payloads removed, then the result equals AC-1.
- **AC-4** (error path) Given an unknown branch, then `not_found`.

## Design

- **Registry command(s):** `journal.diff_branch@1` R0, D0; params `{ source: BranchRef, target: BranchRef }`; result `{ ancestor, added: [EntityDelta], removed: [EntityDelta], changed: [EntityDelta] }`.
- **Data structures:** `EntityDelta { id, target_digest?, source_digest?, target_commands: [CommandRef], source_commands: [CommandRef], conflict: bool }`; `BTreeMap<EntityId, Fold>`.
- **Algorithm:** walk `logical_parent` from both heads, marking visited, until the first shared entry; fold each side's entries in sequence order over entity-tagged output digests (a tombstone digest marks deletion); compare the maps.
- **Errors:** `not_found`, `cancelled`.
- **Determinism:** D0.
- **Performance budget:** diff of two branches with 10,000 entries each since the ancestor in < 200 ms [unverified until measured].
- **Crate:** `fid-journal` (module `diff`).

## Open questions

- Value-level deltas for the Proposal Inbox result layer would come from replay comparison; confirm the split with `VIZ.INBOX`.
- This leaf relies on entity-tagged output digests in the entry header (`CORE.JRN.ENTRY`).
- Build choices (module docs of `fid_journal::diff` pin them): the diff reads verified headers only (CHAIN.VERIFY steps 1 to 14, no blobs, no head cache, no checkpoints); a branch's head is its last `command` or `head_move` entry, else its `created_from`; a `created_from` naming a session header or principal upgrade resolves to the last state entry of that entry's branch at or before it; session headers and principal upgrades are not logical states; a `logical_parent` must name an earlier verified entry; a `head_move` is walked through its verified `head_move.to`, which must equal its `logical_parent` (else `invariant_violated`).
- **Obligation on `CORE.BUS.ROUTE` and `CORE.JRN.UNDO`: no writer sets `logical_parent` yet.** Until ROUTE sets it on every commit (the branch's previous state; a new branch's first entry its `created_from`) and UNDO sets it on every `head_move` (equal to `head_move.to`), every entry is a root and two branches with different heads report `ancestor: null`: real forks are not yet diffed against their common ancestor.
- **AC-3 is only partly met.** The diff itself reads headers only and is unchanged with payloads removed. Branch existence, `created_from` and owner come from `CORE.JRN.BR.NAME`'s origin-bound table, which is folded from event bodies in payloads; the `BranchSource`/`DiffSource` contract (`fid-journal-cmd`) now requires the bus wiring to check replayed events against each header's `events_commit`, but no wiring exists yet, and with payloads removed the table loses what it can no longer prove. Follow-up with the bus wiring and BR.NAME.
- **Cost.** The walk covers the whole stream from sequence 1 (verification needs the chain from genesis), under the store's connection mutex, so cost grows with the journal, not with the entries since the ancestor; the performance budget above cannot hold on a long journal. Follow-up: a windowed walk anchored at a trusted head. Agent (MCP) calls get lower default bounds.
- Without a trusted head a journal rewritten from some entry on, or cut at its tail, cannot be detected (CHAIN.VERIFY's limit); the diff takes an optional trusted head. Until TRUST.VERIFY, the bus passes none.
- The result also names each side (`branch`, `head`, `owner`) and each command reference carries the verified header's principal kind; `VIZ.INBOX` may rely on both.
