# CORE.JRN.UNDO.SUPER: Supersession of released records

## Purpose

A released record is never undone; it is superseded. `journal.supersede_record@1` records that a new released record replaces an old one, citing the old and new record digests and a reason, and leaves the original visible. It is W3, so only a human performs it; agents can only request it.

## Scope

**In:** `journal.supersede_record@1` (W3); the supersession event; the "superseded by" lookup used by readers and the verifier.
**Out:** producing the new record (its owning domain's W3 command); human assertions (`TRUST`); undo barriers (`CORE.JRN.UNDO.MOVE`).

## Requirements

- **REQ-CORE.JRN.UNDO.SUPER-001** `journal.supersede_record@1` shall be side-effect class W3 and shall record the superseded record digest, the new record digest and a commitment to a reason of 1 to 2,000 characters.
- **REQ-CORE.JRN.UNDO.SUPER-002** If either digest does not belong to a record committed by a W3 entry on the branch, or the old record is already superseded, then the command shall return `precondition` with reason `not_supersedable` and commit nothing.
- **REQ-CORE.JRN.UNDO.SUPER-003** When a record is superseded, the journal shall keep the original entry unchanged and visible, and the lookup `superseded_by(digest)` shall return the new digest and the supersession entry.

## Acceptance criteria

- **AC-1** Given fixture `fixtures/core/jrn/undo/super/two_releases` (records R1 and R2 released by W3 test commands), when a human runs `fid journal supersede-record --old <R1> --new <R2> --reason "wrong part revision" --json`, then one W3 entry is appended and `superseded_by(R1)` returns R2; R1's entry is unchanged.
- **AC-2** (error path) Given an agent over MCP, then a pending request is filed and nothing is superseded.
- **AC-3** (error path) Given an old digest that is not a released record, or one already superseded, then `precondition` / `not_supersedable`.
- **AC-4** (replay) Given the journal of AC-1, when replayed in exact mode, then the outcome is `IDENTICAL`.

## Design

- **Registry command(s):** `journal.supersede_record@1` W3, D0, `not_undoable`; params `{ old: Digest, new: Digest, reason: Untrusted<String> }`; result `{ entry }`; projection `request_only`.
- **Data structures:** event `RecordSuperseded { old, new, reason_commit }`; index `superseded_by: BTreeMap<Digest, (Digest, EntryHash)>` rebuilt from events.
- **Algorithm:** look up both digests among W3 entries' outputs; check the index; emit the event.
- **Errors:** `precondition` (`not_supersedable`), `validation`.
- **Determinism:** D0.
- **Performance budget:** < 1 ms [unverified until measured].
- **Crate:** `fid-journal` (module `supersede`).

## Open questions

- Built (2026-11-22): planner, origin-bound fold and definition in `fid_journal::supersede`; bus handler in `fid_journal_cmd::supersede`. The fold follows REQ-CORE.RPL.RECON.FOLD-008: (a) `RecordSuperseded` only from the handler of `journal.supersede_record@1`, W3, human; (b) the event is reserved to that command in `fid_registry::RESERVED_EFFECTS`; (c) refused next to any `Request*` event, so an approved agent request never carries a supersession (the human runs the command); (d) the event carries `head`, the branch's logical head it was decided against, and the fold requires it to be the head before the entry (the commit stage commits only if the head is unchanged, `conflict/head_moved`); (e) a supersession counts on its own branch only, and a promoted copy carrying one is refused; (f) refusals are fatal. Forged cases come from `fixtures/core/jrn/undo/super/make_fixtures.py`.
- Built, deviations: the event is `RecordSuperseded {head, new, old}`. The reason commitment is the entry header's salted `reason_commit` (CORE.JRN.ENTRY), which the fold keeps in the index, not a field of the event: a salted commitment cannot be computed before the entry is built. The result is `{supersession}` (the event body), not `{entry}`: the entry hash is the commit stage's. "Released record" is an output digest of a W3 command entry on the same branch (not the tombstone, not a supersession entry); records reached through a fork are not looked up. A new record that is already superseded is refused too.
- Built, obligations on the bus commit stage (not built): record the `reason` parameter as the entry's `reason`; commit only if the branch head is still the event's `head`; fold the entry with `Supersessions::apply_entry` before commit. AC-1 and AC-4 are met at event and fold level (planning and folding are deterministic); writing the W3 entry and exact-mode replay of the journal need that stage and `CORE.RPL`, as for `CORE.JRN.BR.PROMO`.
- Whether supersession needs a human assertion like protected promotion is for `TRUST` to say; this leaf relies on the W3 class rules only.
