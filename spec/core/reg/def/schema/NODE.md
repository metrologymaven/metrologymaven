# CORE.REG.DEF.SCHEMA: Schema keyword vocabulary, meta-schema and catalogue facade

## Purpose

Fixes the JSON Schema dialect for command parameters and results: JSON Schema 2020-12 plus seven project keywords, published as a meta-schema so that every generator and consumer agrees on it. It also offers a read-only `QuantityCatalogue` facade over the unit catalogue owned by `GEO.FRAME.UNITS`, so registry code, `CORE.BUS.UNIT` and `CORE.STO.SET` look kinds and units up in one place without the registry defining any unit.

## Scope

**In:** keyword semantics and value shapes for `x-quantity`, `x-unit`, `x-ref`, `x-selector`, `x-standards-ref`, `x-ui`, `x-untrusted`; the meta-schema file; a checker that a schema document uses only allowed keywords and valid keyword values; the catalogue facade and its digest.
**Out:** the catalogue content (`GEO.FRAME.UNITS`); the rule that every `number` field carries `x-quantity` (`CORE.REG.VAL`); wrapping untrusted strings at the MCP boundary (`AUTO.MCP.TAINT`); literal normalisation (`CORE.BUS.UNIT`).

## Requirements

- **REQ-CORE.REG.DEF.SCHEMA-001** The registry shall publish `registry-keywords.schema.json`, a JSON Schema 2020-12 meta-schema that admits the standard 2020-12 vocabularies plus exactly the keywords `x-quantity`, `x-unit`, `x-ref`, `x-selector`, `x-standards-ref`, `x-ui` and `x-untrusted`.
- **REQ-CORE.REG.DEF.SCHEMA-002** If a parameter or result schema contains a keyword outside that set, or a `$ref` to a document outside the registry's own schema set, then the schema checker shall report `unknown_keyword` or `external_ref` with the JSON pointer.
- **REQ-CORE.REG.DEF.SCHEMA-003** If an `x-quantity` value is not a kind in the unit catalogue, or an `x-unit` value is not an accepted unit of the sibling `x-quantity` kind, then the schema checker shall report `unknown_quantity` or `unit_not_accepted` with the JSON pointer.
- **REQ-CORE.REG.DEF.SCHEMA-004** The `QuantityCatalogue` facade shall return, for each kind, the canonical SI unit, the accepted authoring units and their exact rational factors exactly as `GEO.FRAME.UNITS` publishes them, and shall add, remove or alter none.
- **REQ-CORE.REG.DEF.SCHEMA-005** The facade shall expose the SHA-256 of the canonical JSON form of the catalogue it serves, for `CORE.REG.MAN` to put in the manifest.
- **REQ-CORE.REG.DEF.SCHEMA-006** `x-untrusted` shall be a boolean allowed only on string-typed schemas; `true` marks content-derived text (CONSTITUTION C6), and an absent marker shall mean "untrusted unless the type is an enum, an ID or a number", as `AUTO.MCP.TAINT` applies it.
- **REQ-CORE.REG.DEF.SCHEMA-007** `x-standards-ref` shall hold only a designator, an edition and an optional clause number, each matching a fixed pattern of at most 64 characters, so that no standards text can be stored in a schema.
- **REQ-CORE.REG.DEF.SCHEMA-008** `x-ref` shall name an entity type and `x-selector` a selector form, each from a closed list in the meta-schema; `x-ui` shall hold presentation hints only and shall not change validation.
- **REQ-CORE.REG.DEF.SCHEMA-009** The schema checker shall reject documents larger than 1 MiB or nested deeper than 64 levels with `schema_too_large` or `schema_too_deep`, without panicking.

## Acceptance criteria

- **AC-1** Given fixture `fixtures/core/reg/def/schema/valid/` (schemas using every project keyword), when checked, then no error is reported and each validates against `registry-keywords.schema.json`.
- **AC-2** (error path) Given `fixtures/core/reg/def/schema/invalid/` (`x_foo_keyword`, `external_ref`, `unknown_quantity`, `angle_unit_on_length`, `untrusted_on_number`, `standards_ref_with_text`, `depth_65`), when checked, then each reports exactly its `expect` code and pointer.
- **AC-3** Given the catalogue fixture of `GEO.FRAME.UNITS`, when the facade lists `length`, then the units and rational factors equal the catalogue's entries one for one (for example `in` = 254/10000).
- **AC-4** Given the same catalogue twice, when the facade digest is computed, then both digests are equal; a one-unit change in the catalogue fixture changes the digest.

## Design

- **Registry command(s):** none; library.
- **Data structures:** `Keyword` enum; `SchemaIssue { pointer, code }`; `QuantityCatalogue` trait object wrapping the `GEO.FRAME.UNITS` tables with `kind(name)`, `accepts(kind, unit)`, `factor(unit) -> Rational`, `digest()`; closed lists `EntityType` and `SelectorForm` (extended by later decisions only through this leaf's meta-schema version).
- **Algorithm:** iterative walk of the schema value with an explicit stack (depth guard); keyword lookup in a sorted table; `x-unit` checked against the nearest enclosing `x-quantity`; `x-standards-ref` pattern `^[A-Z][A-Z0-9 /.-]{1,31}:[0-9]{4}( cl\. [0-9.]{1,16})?$` [unverified that it fits every designator].
- **Errors:** as listed in REQ-002, -003, -009.
- **Determinism:** D0; issues sorted by pointer then code.
- **Performance budget:** check 5,000 schemas in < 1 s [unverified until measured].
- **Crate:** `fid-registry` (module `schema`); depends on `fid-geo-frame` (L0) for the catalogue.
- **Pinned choices (build):**
  - **Modules and files:** `fid-registry` modules `schema` (vocabulary, checker, meta-schema) and `catalogue` (facade); meta-schema `schemas/registry-keywords.schema.json`, the RFC 8785 canonical bytes of `registry_keywords_schema()` plus a newline (a test compares them); fixtures and their generator `fixtures/core/reg/def/schema/make_fixtures.py` (`--check` reports stale files); `tools/check_registry_keywords.py` validates the fixtures against the meta-schema with Python `jsonschema` (run by hand, like `tools/check_command_defs.py`; it skips `depth_65`, whose 65 levels make `jsonschema`'s `unevaluatedProperties` evaluation exponential). No new dependency.
  - **Closed keyword list** (`KEYWORDS`, 64 entries sorted by byte order, binary search, case-sensitive): core `$anchor`, `$comment`, `$defs`, `$dynamicAnchor`, `$dynamicRef`, `$id`, `$ref`, `$schema`, `$vocabulary`; applicator `additionalProperties`, `allOf`, `anyOf`, `contains`, `dependentSchemas`, `else`, `if`, `items`, `not`, `oneOf`, `patternProperties`, `prefixItems`, `properties`, `propertyNames`, `then`; unevaluated `unevaluatedItems`, `unevaluatedProperties`; validation `const`, `dependentRequired`, `enum`, `exclusiveMaximum`, `exclusiveMinimum`, `maxContains`, `maxItems`, `maxLength`, `maxProperties`, `maximum`, `minContains`, `minItems`, `minLength`, `minProperties`, `minimum`, `multipleOf`, `pattern`, `required`, `type`, `uniqueItems`; meta-data `default`, `deprecated`, `description`, `examples`, `readOnly`, `title`, `writeOnly`; `format`; content `contentEncoding`, `contentMediaType`, `contentSchema`; and the seven project keywords. Keywords are checked only at schema positions; names under `properties`, `$defs`, `dependentSchemas`, `patternProperties` and every data value (`const`, `default`, `enum`, `examples`, `x-ui`, the value of an unknown keyword) are not keywords and are not walked as schemas. Outside the list: `definitions`, `dependencies`, `$recursiveAnchor`, `$recursiveRef` (deprecated 2019-09 keywords of the 2020-12 meta-schema) give `bad_dialect` as in `CORE.REG.VAL`; anything else, case variants and `additionalItems` included, gives `unknown_keyword`. The array form of `items` (pre-2020-12) is `bad_schema`.
  - **Standard keyword values** (`bad_schema`): `type` one of the seven type names or a non-empty array of distinct ones; schema positions an object or boolean, maps of schemas objects, lists of schemas non-empty arrays; `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum` numbers, `multipleOf` a positive number (an `I64`/`U64` above 2^53 in magnitude is not a number); the eight count keywords integers `0..=2^53`; `uniqueItems`, `deprecated`, `readOnly`, `writeOnly` booleans; `title`, `description`, `$comment`, `format`, `pattern`, `contentEncoding`, `contentMediaType` strings (patterns are not compiled); `enum`, `examples` arrays; `required` and each `dependentRequired` value an array of distinct strings; `$anchor`, `$dynamicAnchor` match `^[A-Za-z_][-A-Za-z0-9._]*$` (at most 128 bytes); `$vocabulary` an object of booleans; `$id` at the root a string without `#`. Names under `properties`, `$defs`, `dependentSchemas`, in `required` and in `dependentRequired` are non-empty printable ASCII without space [`bad_property_name`]; two keys of one object equal after ASCII lowercasing [`duplicate_key`] (not for `patternProperties` regexes); a non-finite or subnormal number anywhere [`bad_number`]. Empty numeric ranges (`minimum > maximum`) stay `CORE.REG.VAL`'s rule.
  - **Dialect and references** (as `CORE.REG.VAL`): `$schema` only at the root and only `https://json-schema.org/draft/2020-12/schema` [`bad_dialect`]. `$ref` not starting with `#` [`external_ref`]: the registry's own schema set is the schema itself, so no other document is reachable. `#` is the root; `#/<RFC 6901 pointer>` (no `%`; `~` only as `~0` or `~1`; canonical decimal array indices) is resolved after the walk and must land on a schema position of the vocabulary (`$defs` entry, `properties` entry, `allOf` item, ...), else [`unwalked_ref`]; so does a plain-name `#anchor`, any `$dynamicRef`, and an `$id` below the root.
  - **Project keywords** (`bad_keyword_value` for a wrong JSON type or a value outside a closed list): `x-quantity` a string naming a catalogue kind, case-sensitive [`unknown_quantity`]; `x-unit` a string accepted for the `x-quantity` of the same schema object [`unit_not_accepted`, also when that object has none]: "nearest enclosing" is read as the schema object that holds the `x-unit`, because a parent schema describes a different instance location and `CORE.REG.VAL` uses the sibling too; when that `x-quantity` is itself invalid only it is reported. `x-quantity` may sit on any type (authored literals are strings, `CORE.BUS.UNIT`); requiring it on numbers is `CORE.REG.VAL`'s rule. `x-ref` one of `EntityType` = `alignment`, `characteristic`, `datum`, `element`, `feature`, `frame`, `part`, `plan`, `result`, `revision`, `run`; `x-selector` one of `SelectorForm` = `list` (an array of entity IDs), `single` (one entity ID); both lists are version 1 (`REGISTRY_KEYWORDS_VERSION`) and grow only with a new version of this meta-schema. `x-ui` an object whose content is data and never validated or walked. `x-untrusted` a boolean (`true` and `false` both accepted) on a schema whose `type` is `"string"` or an array holding `"string"` and otherwise only `"null"` [`untrusted_on_non_string`]. `x-standards-ref` one string matching `^[A-Z][A-Z0-9 /.-]{1,31}:[0-9]{4}( cl\. [0-9.]{1,16})?$` (at most 58 characters; anything else, a non-string included, is `bad_standards_ref`).
  - **Meta-schema:** `$schema` 2020-12, `$id` `https://metrologymaven.io/schemas/registry-keywords.schema.json`, `$dynamicAnchor: meta`, `allOf: [{"$ref": <2020-12 meta-schema>}]`, the seven project keywords under `properties` with the value rules above, `false` for `$dynamicRef`, `$recursiveAnchor`, `$recursiveRef`, `definitions`, `dependencies`, `$ref` limited to `^#`, `$schema` to the 2020-12 URI, `dependentSchemas` for `x-unit` (needs `x-quantity`) and `x-untrusted` (string type), and `unevaluatedProperties: false`, so every keyword of the 2020-12 vocabularies is admitted and nothing else. The checker is stricter than the meta-schema where a meta-schema cannot express the rule: `$schema` and `$id` position, references landing on walked positions, catalogue membership, case-duplicate keys, names, numbers above 2^53, subnormals, depth and size.
  - **Issues:** `SchemaIssue { pointer, code, message }`; codes (`SchemaCode`) `bad_dialect`, `bad_json`, `bad_keyword_value`, `bad_number`, `bad_property_name`, `bad_schema`, `bad_standards_ref`, `duplicate_key`, `external_ref`, `schema_too_deep`, `schema_too_large`, `too_many_issues`, `unit_not_accepted`, `unknown_keyword`, `unknown_quantity`, `untrusted_on_non_string`, `unwalked_ref` (the build prompt's codes plus the `CORE.REG.VAL` conventions). Pointers and messages are made by `validate`'s helpers: RFC 6901 with every character outside printable ASCII written `\u{..}`, segments cut to 128 bytes and the whole to 512; echoed input cut to 128 bytes, escaped and quoted; messages at most 512 bytes, printable ASCII. `""` points at the whole document. Sorted by pointer, then code, then message (byte order). At most 10,000 issues; a run with more keeps the sorted first 10,000 plus one `too_many_issues` at `""`.
  - **Entry points and limits:** `check_schema(&CValue, &dyn QuantityCatalogue)` and `check_schema_json(&[u8], &dyn QuantityCatalogue)`. The root must be an object (a boolean root schema is refused, as in `CORE.REG.VAL`) [`bad_schema` at `""`]. Size: more than 1 MiB = 1,048,576 bytes [`schema_too_large` at `""`, the only issue]: for bytes their length, for a value the length of its RFC 8785 canonical form, counted iteratively without building it. Depth: the schema object is level 1 and every object or array below adds one; the first container (pre-order) at level 65 is reported once [`schema_too_deep` at its pointer] and nothing below it is checked. Bytes are then pre-scanned by `validate`'s scanner: nesting above `fid-canon`'s 128 levels [`schema_too_deep` at `""`], a number literal that is not finite, underflows to zero or a subnormal, or exceeds 2^53 in magnitude in any notation [`bad_number` at `""`]; then parsed by `fid-canon` (an exact duplicate key [`duplicate_key`], anything else [`bad_json`], at `""`). Iterative walk and resolution, no recursion, no panics.
  - **Catalogue facade:** trait `QuantityCatalogue { kind_names, kind(name) -> Option<&KindInfo>, accepts(kind, unit), factor(unit) -> Option<Factor>, digest() -> fid_types::Digest }`; `KindInfo { name, canonical, units }`, `UnitInfo { symbol, factor }`, `Factor { ratio: Rational, times_pi }`, `Rational` positive and in lowest terms. The build prompt's `factor -> Rational` cannot hold the angle factors, which `GEO.FRAME.UNITS` publishes as Π/k with its 256-bit Π; a factor is therefore a rational times Π or not, and the catalogue carries that Π. One implementation, `Catalogue`, built two ways through the same checks: `Catalogue::geo_frame()` from `fid-geo-frame` (kinds named by `validate::unit_kind`, symbols, `LengthUnit::ratio`, `AngleUnit::per_half_turn`, `PI_256`), and `Catalogue::from_json(bytes)` from a catalogue document, so a catalogue with more kinds is served as published when its owner publishes one. The registry defines no kind, unit or factor; `fid-geo-frame` is unchanged. `Catalogue` also implements `CORE.REG.VAL`'s `QuantityKinds`, so `validate_with` takes the facade in place of `GeoFrameUnits` (same answers for the GEO.FRAME.UNITS catalogue; a test compares them).
  - **Catalogue form and digest:** `{"format":"fid-quantity-catalogue/1","kinds":[{"canonical","kind","units":[{"den","num","pi","symbol"}]}],"pi_hex"}`, kinds sorted by name and units by symbol (byte order), `num`/`den` decimal strings `[1-9][0-9]*` fitting `u64` and in lowest terms, `pi` a boolean, `pi_hex` Π·2^254 as 64 lowercase hex digits with the top bit set. Kind names `^[a-z][a-z0-9_]{0,31}$`; symbols 1 to 16 bytes of printable ASCII without space, unique across the catalogue even after ASCII lowercasing; 1 to 64 units per kind, exactly one with factor 1 (not times Π), which is `canonical`; at most 64 kinds; documents at most 1 MiB and 5 levels deep; exact field sets. Anything else is refused (`bad_catalogue`, `catalogue_too_large`, or the `fid-canon` code); messages never echo input. `digest()` = `sha256:` + SHA-256 of the RFC 8785 canonical bytes of that form.
  - **Fixtures:** `valid/` two schemas using all seven project keywords; `invalid/` the seven AC-2 cases (`unknown_quantity` uses `lenght`, since a real kind name could later join the catalogue); `catalogue/geo_frame_units.json` typed by hand from `GEO.FRAME.UNITS`'s pinned factors and its `.sha256` from Python `hashlib`; `one_unit_changed.json` (thou = 127/500000); `with_time.json`, test data only, adds an invented `time` kind (s, ms, min, h) to show that the facade and `CORE.REG.VAL` accept `x-quantity: time` once a catalogue holds it.
  - **Performance:** 5,000 fixture schemas checked in 256 ms (release build, one desktop x86_64 machine, 2026-11-19).

> In crate `fid-registry`, add module `schema`. Publish `schemas/registry-keywords.schema.json` (JSON Schema 2020-12 meta-schema: standard vocabularies plus `x-quantity`, `x-unit`, `x-ref`, `x-selector`, `x-standards-ref`, `x-ui`, `x-untrusted`). Implement `check_schema(doc, &dyn QuantityCatalogue) -> Vec<SchemaIssue>` that reports `unknown_keyword`, `external_ref`, `unknown_quantity`, `unit_not_accepted`, `untrusted_on_non_string`, `bad_standards_ref`, `schema_too_large` (1 MiB) and `schema_too_deep` (64), sorted by JSON pointer. Implement the `QuantityCatalogue` facade over the unit tables of `fid-geo-frame` (do not define any unit or factor in this crate) with a `digest()` = SHA-256 of the catalogue's canonical JSON. `x-untrusted` is a boolean on strings only; `x-standards-ref` holds designator, edition and clause only (never standards text). Tests AC-1..AC-4. Constraints: CONSTITUTION §2.1 (catalogue owned by GEO.FRAME.UNITS, L0), C6, §5 (no standards text), §8 (no panic, no `unsafe`), iterative walk with depth guard.

## Open questions

- The catalogue in `GEO.FRAME.UNITS` today holds length and angle only; REQ-CORE.REG-004 needs more kinds (time, temperature, dimensionless, count, force). Until GEO.FRAME extends it, `x-quantity` cannot name those kinds (cross-domain request). The facade is ready for them: `Catalogue::from_json` serves any catalogue in the pinned form, so adding kinds needs no registry change; which node publishes that document (GEO.FRAME or a shared catalogue owner) is still open.
- Whether `x-untrusted: false` should be allowed at all, or only `true`, is left to `AUTO.MCP.TAINT`; this leaf accepts both.
