# QUAL.SBOM.COMPLETE: SBOM content policy and completeness check

## Purpose

States what every per-artefact SBOM must contain and proves, for each release candidate, that the SBOMs generated by `ECO.REL.SIGN.SBOM` meet that policy and miss no component. Generation stays in ECO; this leaf is the independent check that QUAL owns under REQ-QUAL-005.

## Scope

**In:**
- Content policy document `security/sbom/POLICY.md` and its machine form `security/sbom/policy.toml` (format, required fields per component, one SBOM per shipped artefact)
- Format: SPDX 2.3 JSON, as chosen jointly with `ECO.REL.SIGN.SBOM`
- Field check per component: name, version, source (download location), licence expression, package URL, digest where the lockfile or native-component file has one
- Completeness check: every package resolved in each release lockfile for the artefact's target and features, and every entry of `native-components.toml` assigned to the artefact, appears in that artefact's SBOM
- One-SBOM-per-artefact check against the package plan
- Report file `sbom/completeness.json`

**Out** (and which node owns it instead):
- Producing and signing the SBOM files (owned by `ECO.REL.SIGN.SBOM`)
- Licence allowlist decisions (owned by `ECO.CI.LIC`)
- Vulnerability scanning and the release gate (owned by `QUAL.SBOM.SCAN`)
- VEX statements (owned by `QUAL.SBOM.VEX`)

## Requirements

- **REQ-QUAL.SBOM.COMPLETE-001** The policy file shall name SPDX 2.3 JSON as the SBOM format and list the required component fields: name, version, download location, licence expression, package URL and checksum.
- **REQ-QUAL.SBOM.COMPLETE-002** When the check runs on a release candidate, the tool shall fail and name the artefact if any artefact in the package plan has no SBOM or more than one SBOM.
- **REQ-QUAL.SBOM.COMPLETE-003** If a component in an SBOM lacks a required field, or lacks a checksum although its lockfile entry or native-component entry has one, then the check shall fail and name the component and field.
- **REQ-QUAL.SBOM.COMPLETE-004** If a package resolved in the artefact's lockfile build graph, or a native component assigned to the artefact, is absent from the artefact's SBOM, then the check shall fail and name the component.
- **REQ-QUAL.SBOM.COMPLETE-005** The tool shall write `sbom/completeness.json` as RFC 8785 canonical JSON listing per artefact the SBOM SHA-256, the component count and every failure, and the same inputs shall give byte-identical output.

## Acceptance criteria

- **AC-1** Given fixture `fixtures/qual/sbom/complete/ok/` (package plan with 2 artefacts, their lockfile graphs, `native-components.toml` and 2 matching SPDX 2.3 documents), when `cargo xtask qual sbom-check --inputs ok/ --out out/` runs, then it exits 0 and `out/sbom/completeness.json` equals `expected.json` byte for byte.
- **AC-2** (error path) Given `missing-crate/` (one crate from the lockfile graph removed from the SBOM), then it exits 1 and the report names that crate and artefact.
- **AC-3** (error path) Given `missing-native/` (a font listed in `native-components.toml` absent), then it exits 1 naming the font.
- **AC-4** (error path) Given `no-purl/` (one package without a package URL), then it exits 1 naming the package and `purl`.
- **AC-5** (error path) Given `extra-sbom/` (two SBOMs for one artefact), then it exits 1 naming the artefact.
- **AC-6** (determinism) Given AC-1 twice with input files listed in different orders, then both reports are byte-identical.
- **AC-7** (joint) Given the SBOM produced by `ECO.REL.SIGN.SBOM` AC-1, then this check passes on it.

## Design

- **Registry command(s):** none; repository tool `cargo xtask qual sbom-check --inputs <dir> --out <dir> [--json]` (W1: writes one report into a local output root). Inputs dir holds `package-plan.json`, per-artefact `cargo-metadata/<artefact>.json` (from `cargo metadata --locked --offline --filter-platform <target>`), `native-components.toml` and `sbom/*.spdx.json`.
- **Data structures:** `Policy { format: "SPDX-2.3", required_fields }`; `ArtefactResult { artefact, sbom_sha256, components, failures: Vec<Failure{ kind: MissingSbom|DuplicateSbom|MissingComponent|MissingField, component, field }> }`; `CompletenessReport { schema: "qual-sbom-completeness/1", release, artefacts }`.
- **Algorithm:** load the package plan; map each artefact to its SBOM by the root package's artefact SHA-256 (SPDX `DESCRIBES` root, see `ECO.REL.SIGN.SBOM` REQ-006); build the expected component set from the resolved graph (name, version) plus native entries; compare with SBOM packages matched by package URL; check fields; sort everything by byte order.
- **Errors:** `SBOM-PARSE(file)`, `SBOM-MISSING(artefact)`, `SBOM-DUPLICATE(artefact)`, `SBOM-COMPONENT(artefact, component)`, `SBOM-FIELD(component, field)`. Exit 0 pass, 1 fail, 2 bad input.
- **Determinism:** D0; no clock, no network, BTreeMap only.
- **Performance budget:** under 5 s for 6 artefacts with 800 components each [unverified].
- **Crate:** `fid-xtask` (module `qual::sbom_complete`).
