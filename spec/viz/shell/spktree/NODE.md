# VIZ.SHELL.SPKTREE: Toolkit spike - element tree with 10k items

## Purpose

One of the three prototype spikes that D-005 requires before egui + winit + wgpu is confirmed. It builds a throwaway element tree of 10 000 items in egui next to a wgpu viewport and measures frame time, interaction and accessibility against fixed pass criteria. Its output is a measured report that feeds a human decision on confirming or reopening D-005; the spike adopts nothing itself.

## Scope

**In:** a prototype tree (virtualised rows, expand and collapse, multi-select, rename in place, drag to reorder, filter box, keyboard navigation, AccessKit exposure) beside a wgpu viewport; a benchmark harness; a results report.
**Out:** the production element tree (`VIZ.SHELL.TREE`); characteristic table spike (`VIZ.SHELL.SPKTABLE`); report designer spike (`VIZ.SHELL.SPKRPT`); the decision itself (maintainers, D-005).

## Requirements

- **REQ-VIZ.SHELL.SPKTREE-001** The spike shall render a tree of 10 000 items, 6 levels deep, with virtualised rows, beside a wgpu viewport drawing 10⁶ points.
- **REQ-VIZ.SHELL.SPKTREE-002** The spike shall measure 95th-percentile UI frame time during continuous scrolling, during expand-all and collapse-all, and during filter typing, on the PLAT H1 shop-floor profile [unverified].
- **REQ-VIZ.SHELL.SPKTREE-003** The spike shall pass only if every measured 95th-percentile frame time is under 33 ms on H1.
- **REQ-VIZ.SHELL.SPKTREE-004** The spike shall verify keyboard navigation (arrows, expand, collapse, select, rename) and that a screen reader on Windows announces item role, name, level and expanded state.
- **REQ-VIZ.SHELL.SPKTREE-005** The spike shall publish a results report with raw timings, hardware, egui and wgpu versions, pass or fail per criterion and observed limitations.

## Acceptance criteria

- **AC-1** Given generated fixture `fixtures/viz/tree-10k` (10 000 items, 6 levels, seed 5), when the benchmark harness runs a 30 s scripted scroll on H1, then it records p95 frame time and the report states pass if under 33 ms.
- **AC-2** Given the same fixture, when expand-all then collapse-all run, then p95 frame time during each is recorded against the same threshold.
- **AC-3** Given the same fixture, when the scripted keyboard sequence runs, then focus and selection reach the expected item IDs listed in the fixture.
- **AC-4** Given Windows Narrator or NVDA, when focus moves through five items, then the manual check log records role, name, level and expanded state for each (manual step, recorded in the report).
- **AC-5** Given any criterion failing, then the report states "fail" with the measured value, and the recommendation section points to D-005's fallback (option B) for the failing screen.

## Design

- **Registry command(s):** none (prototype; it may call a mock registry).
- **Data structures:** synthetic tree items `{ id, parent, name, kind, status }`.
- **Algorithm:** egui virtualised list over a flattened visible-rows array, recomputed only on expand or collapse; wgpu viewport through the paint-callback integration; frame timing via a monotonic clock around each frame.
- **Errors:** not applicable (prototype).
- **Determinism:** N (timings are observed).
- **Performance budget:** p95 frame time < 33 ms on H1 (pass criterion) [unverified].
- **Crate:** `fid-spike-ui` (example binary `tree10k`; throwaway, never a dependency of product crates).

## Test fixtures

`fixtures/viz/tree-10k`: generated by a seeded generator (seed 5), in-repo. H1 hardware: the PLAT reference shop-floor profile (integrated GPU, 16 GB RAM).

## Build prompt

> Create a throwaway crate `fid-spike-ui` with example `tree10k`: an egui + winit + wgpu app with a virtualised tree of 10 000 generated items (6 levels, seed 5) beside a wgpu viewport drawing 10⁶ points. Support expand/collapse, expand-all, multi-select, rename in place, drag to reorder, filter box and full keyboard navigation, and expose the tree through AccessKit. Add a benchmark harness that scripts 30 s scrolling, expand-all/collapse-all and filter typing, and records p95 frame time. Produce `REPORT.md` with hardware, egui and wgpu versions, raw timings, pass/fail per criterion (p95 < 33 ms on the H1 profile; keyboard reachability; screen-reader announcements of role, name, level and expanded state) and limitations. Do not adopt the result: the report is input for the maintainers' confirmation of decision D-005. Rules: no panics or `unsafe`; deny unwrap/expect/panic/todo/unimplemented/unreachable; the crate must not be a dependency of any product crate.
