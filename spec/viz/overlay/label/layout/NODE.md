# VIZ.OVERLAY.LABEL.LAYOUT: Deterministic automatic label layout

## Purpose

`view.layout_labels@1` places every unpinned label of a LabelSet for one view and viewport size so that no two label boxes overlap and no box leaves the viewport. Labels are placed greedily in priority order (NONCONFORMS, then INDETERMINATE, NOT_DECIDABLE, CONFORMS, then labels without a decision; ties by label ID), each at the first free candidate position around its projected anchor. Pinned labels are obstacles and never move. The result is stored as placements in the LabelSet, so the same layout restores with the view.

## Scope

**In:** `view.layout_labels@1` (W2); anchor projection with the view's f64 camera; candidate generation (8 directions at 4 radii); collision test on a uniform grid; priority order; labels that cannot be placed are marked `hidden` (listed in the result) rather than overlapped; placements written to the LabelSet.
**Out:** box sizes (`VIZ.OVERLAY.LABEL.DRAW`); label commands and pinning (`VIZ.OVERLAY.LABEL.MODEL`); camera (`VIZ.VIEW.STATE`).

## Requirements

- **REQ-VIZ.OVERLAY.LABEL.LAYOUT-001** For a view with up to 500 labels, `view.layout_labels@1` shall produce placements in which no two visible label boxes overlap and every visible box lies inside the viewport, within 200 ms on the reference profile [unverified].
- **REQ-VIZ.OVERLAY.LABEL.LAYOUT-002** Labels shall be placed in the order NONCONFORMS, INDETERMINATE, NOT_DECIDABLE, CONFORMS, no decision, ties broken by label ID, so a higher-priority label is never hidden while a lower-priority label is shown in a position it could have used.
- **REQ-VIZ.OVERLAY.LABEL.LAYOUT-003** Pinned placements shall be kept unchanged and treated as obstacles.
- **REQ-VIZ.OVERLAY.LABEL.LAYOUT-004** Running the command twice on the same LabelSet, view state and viewport size shall produce identical placements and the same LabelSet digest.
- **REQ-VIZ.OVERLAY.LABEL.LAYOUT-005** The command shall journal one entry with the view key, viewport size and the new LabelSet digest.

## Acceptance criteria

- **AC-1** Given fixture `fixtures/viz/labels/dense500` (500 labels on one part, mixed decisions, 1920x1080), when `fid view layout-labels --view main --json` runs, then no two visible boxes overlap, all lie in the viewport, and the timing is reported (nightly; informative until measured).
- **AC-2** Given the AC-1 result, then every hidden label has priority lower than or equal to every shown label competing for its candidates (checker in the test).
- **AC-3** Given three pinned labels, then their placements are unchanged after layout.
- **AC-4** Given two runs, then placements and digests are byte-identical; (replay) exact replay is `IDENTICAL`.

## Design

- **Registry command(s):** `view.layout_labels@1`, W2, D0; params `{ set: LabelSetId, view: ViewKey, viewport: { w, h } }`; result `{ digest, placed, hidden: [LabelId] }`.
- **Algorithm:** project anchors (f64, fixed operation order, no FMA); sort by (priority, ID); for each label try candidates in fixed order, testing against occupied cells of a grid with cell size = median box height; record placement in view-relative units.
- **Errors:** `UnknownView`, `UnknownSet`.
- **Determinism:** D0.
- **Performance budget:** REQ-001 [unverified].
- **Crate:** `fid-overlay` (module `label::layout`).
