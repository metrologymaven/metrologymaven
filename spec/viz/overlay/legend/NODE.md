# VIZ.OVERLAY.LEGEND: Kernel legend display and placement

## Purpose

Draw the legend object the kernel emits (bin edges, counts, percentages, statistics, formatter ID, digests) verbatim, and let users place, size and show or hide it through one journaled command. The viewer never computes or re-rounds a legend value.

## Scope

**In:** the legend widget in the viewport overlay, its layout (orientation, corner, size, visibility), `view.set_legend@1`, the canonical comparison test.
**Out:** computing bins, counts and statistics (`SCAN.CMP`); number formatting (`KRN.NUM`); ColorMapSpec (`VIZ.OVERLAY.CMAP`); legends in report pages (`RPT`).

## Requirements

- **REQ-VIZ.OVERLAY.LEGEND-001** The legend shall display bin edges, counts, percentages and statistics exactly as the strings in the kernel-emitted legend object, with no recomputation or re-rounding.
- **REQ-VIZ.OVERLAY.LEGEND-002** The legend's displayed content, serialised canonically, shall be byte-identical to the kernel legend for the same ColorMapSpec digest and deviation-field digest.
- **REQ-VIZ.OVERLAY.LEGEND-003** `view.set_legend@1` shall set legend visibility, anchor corner, orientation and size for a viewport and shall be journaled.
- **REQ-VIZ.OVERLAY.LEGEND-004** If the kernel legend digest does not match the active ColorMapSpec and field digests, then the legend shall show an "updating" badge and shall not show counts from the stale legend.
- **REQ-VIZ.OVERLAY.LEGEND-005** The legend shall show the colour-map palette ID, the display unit and the formatter ID.

## Acceptance criteria

- **AC-1** Given fixture `fixtures/viz/devfield-10k` (synthetic deviation field, 10 000 points, seed 11) with ColorMapSpec `cmap-5bin` and its kernel legend `legend-5bin.json`, when the legend widget's display model is serialised in RFC 8785 canonical JSON, then it is byte-identical to the kernel legend's canonical form.
- **AC-2** Given the same fixture, when `fid view set-legend --viewport main --anchor top-right --orientation vertical --json` runs, then the result reports the new layout and the journal holds one `view.set_legend@1` entry.
- **AC-3** (replay) Given the journal from AC-2, when replayed in exact mode, then the outcome is `IDENTICAL`.
- **AC-4** (staleness) Given a ColorMapSpec change whose kernel legend has not arrived, when the frame is drawn, then the legend shows the "updating" badge and no counts.
- **AC-5** (error path) Given `--anchor middle`, when the command runs, then it fails with error `InvalidAnchor` and journals nothing.

## Design

- **Registry command(s):** `view.set_legend@1`, W2. Parameters: `viewport: ViewportId`, `visible: bool?`, `anchor: TopLeft|TopRight|BottomLeft|BottomRight?`, `orientation: Vertical|Horizontal?`, `size_px: u32 (80..=800)?`. Result: `LegendLayout`.
- **Data structures:** `LegendLayout`; `LegendDisplayModel` (a view over the kernel `Legend`, never a copy with new numbers).
- **Algorithm:** check legend digests against active spec and field; if matched, lay out kernel strings into rows; if not, render updating state.
- **Errors:** `InvalidAnchor`, `SizeOutOfRange`, `UnknownViewport`.
- **Determinism:** D0 (layout state is pure data; display text is kernel text).
- **Performance budget:** legend layout under 1 ms per frame [unverified].
- **Crate:** `fid-overlay`.

## Test fixtures

`fixtures/viz/devfield-10k`, `cmap-5bin`, `legend-5bin.json`: generated by a seeded generator (seed 11) and a kernel run in the test harness; in-repo, no external licence.
